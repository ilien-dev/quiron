# Sobrevivir en Swift: Parte 1

Aprender un lenguaje nuevo tiene algo de mudarse a otro país. Al principio todo parece familiar (hay variables, funciones, bucles), pero enseguida te encuentras con costumbres locales que no entiendes: signos de interrogación por todas partes, palabras como `guard` o `let` usadas de formas extrañas, y un compilador que se queja de cosas que en otros lenguajes pasarían desapercibidas.

Esta serie, *Sobrevivir en Swift*, está pensada para desarrolladores que ya programan en otro lenguaje (JavaScript, Java, Kotlin, Python...) y quieren llegar rápido a un punto en el que puedan leer y escribir Swift sin sentirse perdidos. No pretende ser una referencia completa, sino una guía de supervivencia: lo que necesitas saber para no ahogarte en tus primeras semanas.

En esta primera parte vamos a cubrir los fundamentos: constantes y variables, tipos, opcionales, control de flujo y funciones.

## Preparando el terreno

La forma más cómoda de experimentar con Swift es usar un **Playground** en Xcode (Archivo → Nuevo → Playground). Escribes código y ves el resultado al instante en el panel lateral. Si no tienes un Mac, puedes instalar Swift en Linux o Windows desde swift.org y usar la terminal:

```bash
swift repl
```

O guardar tu código en un archivo `main.swift` y ejecutarlo con `swift main.swift`.

## `let` y `var`: la primera decisión

En Swift declaras valores de dos maneras:

```swift
let nombre = "Lucía"   // constante
var edad = 30          // variable

edad = 31              // correcto
nombre = "Ana"         // error: no se puede asignar a una constante 'let'
```

La regla de oro es: **usa `let` siempre que puedas**. Solo cambia a `var` cuando realmente necesites modificar el valor. El compilador incluso te avisará si declaras un `var` que nunca cambias. Esto parece un detalle, pero tiene consecuencias: el código con más constantes es más fácil de razonar, porque sabes que un valor no va a cambiar a tus espaldas.

## Inferencia de tipos

Swift es un lenguaje de tipado estático, pero rara vez tendrás que escribir los tipos, porque el compilador los infiere:

```swift
let ciudad = "Buenos Aires"  // String
let habitantes = 3_000_000   // Int
let temperatura = 22.5       // Double
let esCapital = true         // Bool
```

Si quieres o necesitas ser explícito:

```swift
let precio: Double = 10
let apodo: String
apodo = "Luchi"  // se puede asignar una sola vez más tarde
```

Un punto que sorprende a los que vienen de JavaScript: Swift **no hace conversiones implícitas** entre tipos numéricos.

```swift
let entero = 5
let decimal = 2.5
let resultado = entero * decimal          // error
let resultado = Double(entero) * decimal  // correcto: 12.5
```

Al principio resulta molesto, pero elimina toda una categoría de errores sutiles.

## Strings

Los strings en Swift tienen algunas particularidades. La interpolación se hace con `\()`:

```swift
let producto = "café"
let cantidad = 3
print("Pediste \(cantidad) \(producto)s")  // Pediste 3 cafés
```

Y los strings multilínea usan triple comilla:

```swift
let mensaje = """
Hola,
esto es un texto
de varias líneas.
"""
```

Una advertencia importante: en Swift **no puedes acceder a un carácter con un índice entero** como `texto[0]`. Esto se debe a que los strings están compuestos por caracteres Unicode de tamaño variable (un emoji o una letra con tilde pueden ocupar varios bytes). Para obtener el primer carácter usas `texto.first`, y para posiciones arbitrarias, `String.Index`:

```swift
let saludo = "Hola"
let primera = saludo.first                                   // Optional("H")
let tercera = saludo[saludo.index(saludo.startIndex, offsetBy: 2)]  // "l"
```

Sí, es más verboso. Es el precio de manejar Unicode correctamente.

## Colecciones

Las tres colecciones básicas son arrays, diccionarios y sets:

```swift
var lenguajes = ["Swift", "Kotlin", "Rust"]
lenguajes.append("Go")
print(lenguajes.count)  // 4

var capitales = ["España": "Madrid", "Argentina": "Buenos Aires"]
capitales["Chile"] = "Santiago"

var etiquetas: Set = ["ios", "swift", "ios"]
print(etiquetas.count)  // 2
```

Si declaras una colección con `let`, es completamente inmutable: no puedes añadir ni quitar elementos.

Un detalle crucial: los arrays, diccionarios y strings en Swift son **tipos por valor**, no por referencia. Al asignarlos a otra variable se copian:

```swift
var a = [1, 2, 3]
var b = a
b.append(4)
print(a)  // [1, 2, 3]
print(b)  // [1, 2, 3, 4]
```

Si vienes de JavaScript o Java, esto puede sorprenderte, porque allí `a` también habría cambiado. (Internamente Swift usa *copy-on-write*, así que la copia solo ocurre de verdad cuando modificas uno de los dos).

## Opcionales: el gran obstáculo

Si hay un concepto que define a Swift, son los **opcionales**. Y es también donde la mayoría de principiantes se atascan, así que vamos con calma.

En muchos lenguajes, cualquier variable puede ser `null`. Eso provoca el famoso error de referencia nula, que Tony Hoare llamó "el error del billón de dólares". Swift lo resuelve de raíz: **una variable normal nunca puede ser nil**. Si un valor puede estar ausente, tienes que declararlo explícitamente como opcional con `?`:

```swift
var nombre: String = "Ana"
nombre = nil  // error

var apellido: String? = "García"
apellido = nil  // correcto
```

`String?` no es un `String`. Es una caja que puede contener un `String` o estar vacía. Y no puedes usar lo que hay dentro sin abrir antes la caja:

```swift
let texto: String? = "hola"
print(texto.count)  // error: el valor de tipo opcional debe desenvolverse
```

Hay varias formas de "desenvolver" un opcional.

### `if let`

La más común:

```swift
if let texto = texto {
    print(texto.count)  // aquí texto es String, no String?
} else {
    print("No hay texto")
}
```

Desde Swift 5.7 puedes abreviarlo:

```swift
if let texto {
    print(texto.count)
}
```

### `guard let`

`guard` es como un `if` al revés: comprueba una condición y, si no se cumple, **obliga** a salir del ámbito actual (con `return`, `throw`, `break` o `continue`):

```swift
func saludar(_ nombre: String?) {
    guard let nombre else {
        print("No sé cómo te llamas")
        return
    }
    print("Hola, \(nombre)")
}
```

La ventaja es que después del `guard`, `nombre` está disponible ya desenvuelto durante el resto de la función, sin anidar llaves. En el código Swift real verás `guard` constantemente, sobre todo al principio de las funciones para validar entradas.

### El operador `??`

Para dar un valor por defecto:

```swift
let apodo: String? = nil
let mostrar = apodo ?? "Anónimo"  // "Anónimo"
```

### Encadenamiento opcional

Con `?.` puedes acceder a propiedades de algo que podría ser nil. Si cualquier eslabón es nil, el resultado completo es nil:

```swift
let longitud = apodo?.count  // Int?
```

### Desenvolvimiento forzado: `!`

Por último, puedes forzar la apertura de un opcional con `!`:

```swift
let numero = Int("42")!
```

Si el valor es nil, la aplicación **se cuelga**. Es la única vía de escape del sistema de seguridad, así que úsala solo cuando tengas la certeza absoluta de que el valor existe. Una buena regla para sobrevivir: cada vez que escribas `!`, pregúntate si no sería mejor un `guard let`.

Fíjate, por cierto, en que `Int("42")` devuelve un `Int?`. Muchas funciones de la librería estándar devuelven opcionales cuando la operación puede fallar, y el sistema de tipos te obliga a manejar ese caso. Es incómodo durante la primera semana y un alivio el resto de tu vida.

## Control de flujo

### Condicionales

Los `if` no necesitan paréntesis, pero las llaves son obligatorias:

```swift
let nota = 7
if nota >= 9 {
    print("Sobresaliente")
} else if nota >= 5 {
    print("Aprobado")
} else {
    print("Suspenso")
}
```

Además, la condición tiene que ser un `Bool` de verdad. Nada de `if numero {` como en C o JavaScript.

### `switch`

El `switch` de Swift es mucho más potente que en otros lenguajes. No necesita `break` (no hay caída al siguiente caso por defecto), tiene que ser **exhaustivo** y admite rangos, tuplas y condiciones:

```swift
let edad = 25
switch edad {
case 0..<13:
    print("Niño")
case 13..<18:
    print("Adolescente")
case 18...64:
    print("Adulto")
default:
    print("Mayor")
}

let punto = (0, 5)
switch punto {
case (0, 0):
    print("Origen")
case (0, let y):
    print("Sobre el eje Y, en \(y)")
case (let x, 0):
    print("Sobre el eje X, en \(x)")
case let (x, y) where x == y:
    print("En la diagonal")
default:
    print("En otro sitio")
}
```

### Bucles

El bucle `for` clásico de C no existe. En su lugar, `for-in` recorre secuencias y rangos:

```swift
for i in 1...5 {
    print(i)  // 1, 2, 3, 4, 5
}

for i in 0..<3 {
    print(i)  // 0, 1, 2
}

for lenguaje in lenguajes {
    print(lenguaje)
}

for (pais, capital) in capitales {
    print("\(capital) es la capital de \(pais)")
}

for (indice, lenguaje) in lenguajes.enumerated() {
    print("\(indice): \(lenguaje)")
}
```

`...` es un rango cerrado (incluye el final) y `..<` es semiabierto (lo excluye). También existen `while` y `repeat-while` (el equivalente a `do-while`).

## Funciones

Aquí es donde Swift tiene una de sus peculiaridades más visibles: las **etiquetas de argumento**.

```swift
func saludar(persona: String, desde ciudad: String) -> String {
    return "Hola \(persona), saludos desde \(ciudad)"
}

saludar(persona: "Marta", desde: "Lima")
```

Cada parámetro puede tener dos nombres: una etiqueta externa, que se usa al llamar a la función (`desde`), y un nombre interno, que se usa dentro del cuerpo (`ciudad`). Si solo pones uno, se usa para ambas cosas (`persona`). Y si no quieres etiqueta externa, usas `_`:

```swift
func cuadrado(_ n: Int) -> Int {
    n * n  // el return es implícito en funciones de una sola expresión
}

cuadrado(4)  // 16
```

El objetivo es que las llamadas se lean como frases en inglés: `mover(desde: a, hasta: b)`, `insert(elemento, at: 0)`. Al principio parece un capricho, pero en proyectos grandes mejora mucho la legibilidad.

Las funciones también admiten valores por defecto y pueden devolver tuplas:

```swift
func dividir(_ a: Int, entre b: Int = 2) -> (cociente: Int, resto: Int) {
    (a / b, a % b)
}

let r = dividir(17, entre: 5)
print(r.cociente, r.resto)  // 3 2
print(dividir(9).cociente)  // 4
```

### Closures

Los closures son funciones anónimas, equivalentes a las funciones flecha de JavaScript o a las lambdas de otros lenguajes:

```swift
let numeros = [5, 2, 8, 1]
let ordenados = numeros.sorted { $0 < $1 }
let dobles = numeros.map { $0 * 2 }
let pares = numeros.filter { $0 % 2 == 0 }
```

`$0` y `$1` son nombres abreviados para los argumentos. Cuando el closure es el último argumento de una función, puedes escribirlo fuera de los paréntesis (se llama *trailing closure*), que es lo que hemos hecho arriba. Lo verás por todas partes, especialmente en SwiftUI.

## Resumen de supervivencia

Si tuvieras que quedarte con cinco ideas de esta primera parte, serían estas:

1. **`let` por defecto**, `var` solo cuando haga falta.
2. **Los tipos no se convierten solos**: `Double(entero)` cuando mezcles números.
3. **Los opcionales son cajas**: ábrelas con `if let`, `guard let` o `??`, y desconfía del `!`.
4. **Arrays, diccionarios y strings se copian** al asignarlos.
5. **Las etiquetas de argumento** son parte del nombre de la función.
