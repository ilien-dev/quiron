# Svelte: un nuevo framework para crear aplicaciones web mejoradas

En el ecosistema de JavaScript aparece un nuevo framework prácticamente cada semana. La mayoría pasan sin pena ni gloria, pero de vez en cuando surge uno que propone una forma realmente distinta de hacer las cosas. Svelte es uno de esos casos.

Creado por Rich Harris, Svelte no intenta ser "un React más rápido" ni "un Vue más sencillo". Su propuesta es cambiar el lugar donde ocurre el trabajo: en lugar de hacerlo en el navegador, lo hace en el momento de compilar. En este artículo vamos a ver qué significa eso, cómo se escribe un componente en Svelte y por qué vale la pena prestarle atención.

## El problema del DOM virtual

Para entender Svelte primero hay que entender qué hacen los frameworks tradicionales.

React y Vue, por ejemplo, utilizan un **DOM virtual**: una representación en memoria de la interfaz. Cada vez que cambia el estado, el framework genera un nuevo árbol virtual, lo compara con el anterior (el famoso *diffing*) y aplica al DOM real solo las diferencias.

Este enfoque funciona muy bien y fue una revolución en su momento, pero tiene un coste:

- El navegador tiene que descargar y ejecutar el código del framework (el *runtime*), que puede pesar decenas de kilobytes.
- Cada actualización implica crear objetos, compararlos y recorrer árboles, aunque solo haya cambiado un número en pantalla.
- El desarrollador a menudo tiene que optimizar manualmente con herramientas como `useMemo`, `React.memo` o `shouldComponentUpdate` para evitar renderizados innecesarios.

Rich Harris lo resumió en una frase provocadora: *el DOM virtual es puro overhead*.

## La propuesta de Svelte: un compilador

Svelte se define a sí mismo como un **compilador**, no como un framework en el sentido tradicional. Tú escribes componentes en archivos `.svelte` con una sintaxis muy parecida a HTML, CSS y JavaScript normales, y en el momento de construir la aplicación, Svelte los convierte en código JavaScript imperativo y optimizado que actualiza el DOM directamente.

El resultado es que en el navegador **no hay framework**. No hay DOM virtual, no hay diffing. Solo hay pequeñas funciones que saben exactamente qué nodo del DOM tienen que modificar cuando cambia una variable concreta.

Las ventajas son claras:

- **Bundles más pequeños**: una aplicación sencilla puede pesar unos pocos kilobytes.
- **Mejor rendimiento**: las actualizaciones son quirúrgicas.
- **Menos código**: el compilador se encarga de gran parte del trabajo repetitivo.

## Tu primer componente

Veamos un contador, el "hola mundo" de los frameworks reactivos:

```svelte
<script>
  let contador = 0;

  function incrementar() {
    contador += 1;
  }
</script>

<button on:click={incrementar}>
  Has hecho clic {contador} {contador === 1 ? 'vez' : 'veces'}
</button>

<style>
  button {
    background: #ff3e00;
    color: white;
    border: none;
    padding: 0.75rem 1.5rem;
    border-radius: 6px;
    font-size: 1rem;
  }
</style>
```

Fíjate en varias cosas:

1. No hay `import` de ningún framework.
2. No hay `useState` ni `this.setState`. El estado es una variable normal declarada con `let`.
3. Para actualizar la interfaz basta con **asignar** un nuevo valor a la variable. El compilador detecta la asignación y genera el código necesario para actualizar el DOM.
4. Los estilos dentro de `<style>` están **encapsulados** por defecto: solo afectan a este componente, sin necesidad de CSS Modules ni librerías de CSS-in-JS.

## Reactividad declarativa

Svelte tiene una sintaxis especial para valores derivados, usando la etiqueta `$:` (que, curiosamente, es JavaScript válido: una etiqueta de sentencia):

```svelte
<script>
  let ancho = 10;
  let alto = 5;

  $: area = ancho * alto;
  $: if (area > 100) {
    console.log('¡Área grande!');
  }
</script>

<input type="number" bind:value={ancho} />
<input type="number" bind:value={alto} />
<p>El área es {area}</p>
```

Cada vez que `ancho` o `alto` cambian, `area` se recalcula automáticamente. No hay que declarar dependencias a mano como en el array de `useEffect`: el compilador las deduce analizando el código.

Y ese `bind:value` que ves es el **enlace bidireccional**: el valor del input y la variable se mantienen sincronizados en ambas direcciones, sin escribir manejadores de eventos.

> **Nota:** en Svelte 5 se introdujeron las *runes* (`$state`, `$derived`, `$effect`), que hacen la reactividad más explícita y funcionan también fuera de los componentes. La sintaxis que vemos aquí sigue funcionando en modo de compatibilidad, pero si empiezas un proyecto nuevo vale la pena conocer ambas.

## Lógica en las plantillas

Svelte usa bloques especiales para condicionales, bucles y promesas:

```svelte
<script>
  let usuarios = [
    { id: 1, nombre: 'Ana' },
    { id: 2, nombre: 'Luis' },
    { id: 3, nombre: 'Marta' }
  ];
  let mostrar = true;

  async function obtenerDatos() {
    const res = await fetch('https://api.example.com/datos');
    return res.json();
  }

  let promesa = obtenerDatos();
</script>

{#if mostrar}
  <ul>
    {#each usuarios as usuario (usuario.id)}
      <li>{usuario.nombre}</li>
    {/each}
  </ul>
{:else}
  <p>Lista oculta</p>
{/if}

{#await promesa}
  <p>Cargando...</p>
{:then datos}
  <p>Recibidos {datos.length} elementos</p>
{:catch error}
  <p>Error: {error.message}</p>
{/await}
```

El bloque `{#await}` es especialmente cómodo: gestionar los estados de carga, éxito y error de una petición se convierte en algo declarativo y muy legible.

## Comunicación entre componentes

Las props se declaran con `export let`:

```svelte
<!-- Saludo.svelte -->
<script>
  export let nombre = 'desconocido';
</script>

<h2>Hola, {nombre}</h2>
```

```svelte
<!-- App.svelte -->
<script>
  import Saludo from './Saludo.svelte';
</script>

<Saludo nombre="Carla" />
```

Para compartir estado entre componentes que no tienen relación directa, Svelte incluye los **stores**, un mecanismo muy ligero:

```javascript
// store.js
import { writable } from 'svelte/store';
export const tema = writable('claro');
```

```svelte
<script>
  import { tema } from './store.js';
</script>

<p>Tema actual: {$tema}</p>
<button on:click={() => tema.set($tema === 'claro' ? 'oscuro' : 'claro')}>
  Cambiar tema
</button>
```

El prefijo `$` suscribe automáticamente el componente al store y cancela la suscripción cuando el componente se destruye. Sin Redux, sin providers, sin boilerplate.

## Animaciones y transiciones incluidas

Otra de las joyas de Svelte es que trae transiciones integradas:

```svelte
<script>
  import { fade, fly } from 'svelte/transition';
  let visible = true;
</script>

<label>
  <input type="checkbox" bind:checked={visible} /> Mostrar
</label>

{#if visible}
  <p transition:fly={{ y: 200, duration: 500 }}>¡Vuelo hacia dentro!</p>
{/if}
```

Con una sola directiva consigues animaciones de entrada y salida que en otros frameworks requerirían una librería adicional.

## Empezar un proyecto

La forma recomendada de crear una aplicación hoy es usar **SvelteKit**, el meta-framework oficial (el equivalente a Next.js para React o Nuxt para Vue):

```bash
npx sv create mi-app
cd mi-app
npm install
npm run dev
```

SvelteKit añade enrutado basado en archivos, renderizado en servidor, generación estática, carga de datos y despliegue en múltiples plataformas mediante adaptadores.

Si solo quieres experimentar, el tutorial interactivo de la web oficial (svelte.dev) es probablemente uno de los mejores tutoriales de cualquier framework: aprendes escribiendo código directamente en el navegador.

## ¿Cuándo elegir Svelte?

Svelte encaja especialmente bien en:

- **Aplicaciones donde el rendimiento y el tamaño importan**: dispositivos móviles de gama baja, conexiones lentas, widgets embebidos en otras páginas.
- **Proyectos pequeños y medianos** donde la simplicidad acelera el desarrollo.
- **Equipos que empiezan** con el desarrollo frontend, ya que la curva de aprendizaje es muy suave: si sabes HTML, CSS y JavaScript, sabes casi todo Svelte.
- **Visualizaciones de datos** e interfaces interactivas. No es casualidad que Rich Harris trabajara en el equipo de gráficos de The New York Times.

También hay que ser honestos con sus limitaciones:

- **El ecosistema es más pequeño** que el de React. Encontrarás menos librerías de componentes y menos respuestas en Stack Overflow.
- **El mercado laboral** está dominado por React, Angular y Vue. Hay ofertas de Svelte, pero muchas menos.
- **Requiere un paso de compilación**, así que no puedes simplemente incluir un `<script>` en una página como con Vue o Alpine.

## Conclusión

Svelte demuestra que hay otra manera de construir interfaces reactivas. Al trasladar el trabajo del navegador al compilador, consigue aplicaciones más ligeras y rápidas, y al mismo tiempo ofrece una de las experiencias de desarrollo más agradables del ecosistema: menos código, menos conceptos y menos configuración.

No hace falta abandonar tu framework actual para aprovecharlo. Prueba a construir un proyecto pequeño, un componente aislado o una herramienta interna. Es muy probable que, cuando vuelvas a escribir `useEffect` con su array de dependencias, eches de menos la sencillez de una simple asignación.
