Si llevas un tiempo en el desarrollo frontend, seguramente has pasado por React, Vue o Angular. Todos resuelven el mismo problema, mantener la interfaz sincronizada con el estado, y todos lo hacen de una forma parecida: envían al navegador una librería que, en tiempo de ejecución, decide qué partes del DOM hay que actualizar.

Svelte propone otra cosa. No es exactamente un recién llegado (Rich Harris lo publicó en 2016), pero su planteamiento sigue siendo novedoso, y con Svelte 5 y su sistema de *runes* el framework se ha reinventado casi por completo. En este post te cuento qué lo hace distinto, cómo se ve el código y cuándo tiene sentido elegirlo.

## Un compilador, no una librería

La idea central de Svelte es sencilla: **el trabajo se hace en la compilación, no en el navegador**.

En un framework tradicional, tu aplicación viaja junto con el runtime del framework. Cuando el estado cambia, ese runtime compara árboles virtuales (el famoso Virtual DOM), calcula las diferencias y aplica los cambios.

Svelte analiza tus componentes durante el build y genera JavaScript que actualiza directamente los nodos del DOM afectados. No hay Virtual DOM ni proceso de *diffing*. El resultado tiene tres ventajas:

- **Bundles más pequeños**: solo se envía el código que tu aplicación usa.
- **Mejor rendimiento**: las actualizaciones son quirúrgicas, sin comparaciones intermedias.
- **Menos código que escribir**: el compilador se encarga de buena parte del trabajo repetitivo.

## Tu primer componente

Un componente de Svelte vive en un archivo `.svelte` y combina lógica, marcado y estilos:

```svelte
<script>
  let count = $state(0);
  let doubled = $derived(count * 2);
</script>

<button onclick={() => count++}>
  Has hecho clic {count} veces
</button>

<p>El doble es {doubled}</p>

<style>
  button {
    padding: 0.5rem 1rem;
    border-radius: 6px;
  }
</style>
```

Aquí no hay `useState`, `setCount`, arrays de dependencias ni `this`. Declaras una variable, la modificas con `count++` y la interfaz se actualiza.

Los estilos tienen *scope* automático: ese selector `button` solo afecta a los botones de este componente. No necesitas CSS Modules, BEM ni librerías de CSS-in-JS.

## Runes: la reactividad de Svelte 5

Las *runes* son la gran novedad de Svelte 5. Son símbolos con el prefijo `$` que le indican al compilador qué es reactivo. Las cuatro que usarás a diario son estas.

### `$state`

Declara estado reactivo. Funciona con primitivos, objetos y arrays, y la reactividad es profunda:

```svelte
<script>
  let tareas = $state([
    { texto: 'Aprender Svelte', hecha: false }
  ]);

  function agregar(texto) {
    tareas.push({ texto, hecha: false });
  }
</script>
```

Un `push` sobre el array dispara la actualización. No hace falta crear copias inmutables ni usar el operador *spread*.

### `$derived`

Define valores calculados a partir de otros. Se recalculan solo cuando cambian sus dependencias, y Svelte las detecta automáticamente:

```js
let pendientes = $derived(tareas.filter((t) => !t.hecha).length);
```

### `$effect`

Ejecuta efectos secundarios cuando cambia el estado que lee:

```js
$effect(() => {
  document.title = `${pendientes} tareas pendientes`;
});
```

No hay array de dependencias que mantener a mano, así que desaparecen los bugs por olvidar una. Un consejo: úsalo con moderación. Si puedes expresar algo con `$derived`, hazlo así.

### `$props`

Recibe las propiedades del componente con desestructuración normal de JavaScript, incluidos los valores por defecto:

```svelte
<script>
  let { nombre = 'mundo', destacado = false } = $props();
</script>

<h1 class:destacado>Hola, {nombre}</h1>
```

Una ventaja importante de las runes es que funcionan fuera de los componentes. En archivos `.svelte.js` o `.svelte.ts` puedes crear lógica reactiva reutilizable:

```js
// contador.svelte.js
export function crearContador() {
  let valor = $state(0);

  return {
    get valor() {
      return valor;
    },
    incrementar: () => valor++
  };
}
```

Con esto, muchas aplicaciones no necesitan una librería externa de gestión de estado.

## Plantillas expresivas

El marcado de Svelte es HTML con algunos añadidos. Las estructuras de control se leen con facilidad:

```svelte
{#if tareas.length === 0}
  <p>No tienes tareas. ¡Disfruta el día!</p>
{:else}
  <ul>
    {#each tareas as tarea (tarea.texto)}
      <li>
        <input type="checkbox" bind:checked={tarea.hecha} />
        {tarea.texto}
      </li>
    {/each}
  </ul>
{/if}
```

La directiva `bind:` crea un enlace bidireccional entre el input y el estado. En formularios ahorra una cantidad notable de código.

También hay bloques `{#await}` para manejar promesas en la plantilla y *snippets* para reutilizar fragmentos de marcado dentro de un componente.

## Animaciones incluidas

Svelte trae transiciones y animaciones de serie. Para que un elemento aparezca y desaparezca con un fundido:

```svelte
<script>
  import { fade, fly } from 'svelte/transition';
  let visible = $state(true);
</script>

<button onclick={() => (visible = !visible)}>Alternar</button>

{#if visible}
  <div transition:fade>Aparezco suavemente</div>
  <div in:fly={{ y: 20 }} out:fade>Entro volando</div>
{/if}
```

Como el compilador solo incluye lo que importas, si no usas transiciones no añaden peso al bundle.

## SvelteKit: el framework de aplicación

Svelte se ocupa de los componentes. Para construir una aplicación completa existe **SvelteKit**, el equivalente a Next.js o Nuxt en este ecosistema. Ofrece:

- **Enrutamiento basado en archivos**: cada carpeta dentro de `src/routes` es una ruta.
- **Renderizado flexible**: SSR, generación estática, SPA o una mezcla, configurable por página.
- **Carga de datos integrada** mediante funciones `load`.
- **Form actions** para procesar formularios en el servidor con mejora progresiva.
- **Adaptadores** para desplegar en Node, Vercel, Netlify, Cloudflare y otros.

Una página que carga datos en el servidor se ve así:

```js
// src/routes/blog/+page.server.js
export async function load({ fetch }) {
  const res = await fetch('/api/posts');
  return { posts: await res.json() };
}
```

```svelte
<!-- src/routes/blog/+page.svelte -->
<script>
  let { data } = $props();
</script>

<h1>Blog</h1>

{#each data.posts as post}
  <article>
    <h2><a href="/blog/{post.slug}">{post.titulo}</a></h2>
    <p>{post.resumen}</p>
  </article>
{/each}
```

El servidor obtiene los datos, renderiza el HTML y el cliente lo hidrata. Si usas TypeScript, los tipos de `data` se generan automáticamente a partir de lo que devuelve `load`.

## Cómo empezar

Crear un proyecto lleva menos de un minuto con la CLI oficial:

```bash
npx sv create mi-app
cd mi-app
npm install
npm run dev
```

El asistente te pregunta si quieres TypeScript, ESLint, Prettier, Tailwind, Vitest o Playwright, y lo deja configurado. Por debajo usa Vite, así que el servidor de desarrollo arranca al instante y el *hot reload* es muy rápido.

Si prefieres probar sin instalar nada, el [tutorial interactivo oficial](https://svelte.dev/tutorial) y el *playground* de svelte.dev funcionan en el navegador.

## ¿Cuándo elegir Svelte?

Svelte encaja especialmente bien cuando:

- **El rendimiento y el peso importan**: sitios de contenido, e-commerce, aplicaciones para móviles o conexiones lentas.
- **El equipo es pequeño** y quiere avanzar rápido con poco *boilerplate*.
- **Construyes widgets o componentes embebidos**, donde cada kilobyte cuenta.
- **Estás aprendiendo**: su curva de aprendizaje es de las más suaves, porque se apoya en HTML, CSS y JavaScript que ya conoces.

También hay límites que conviene conocer:

- **El ecosistema es más pequeño** que el de React. Hay librerías de componentes sólidas, pero menos variedad.
- **El mercado laboral es menor**, aunque crece cada año.
- **Migrar código de Svelte 3 o 4 lleva trabajo**. La sintaxis antigua sigue funcionando y hay una herramienta de migración automática, pero las runes son un cambio de modelo mental.

## Conclusión

Svelte demuestra que un framework no tiene por qué cargar con un runtime pesado. Al trasladar el trabajo al compilador, consigue aplicaciones más ligeras y un código más corto y legible.

Con Svelte 5, la reactividad es explícita, predecible y reutilizable fuera de los componentes. Con SvelteKit tienes además lo necesario para llevar un proyecto a producción.

Mi recomendación es dedicar una tarde al tutorial oficial y construir algo pequeño, como una lista de tareas o un buscador.
