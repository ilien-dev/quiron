# Tutorial: Aplicaciones de Angular CLI con Bootstrap

En este tutorial vamos a ver, paso a paso, cómo integrar Bootstrap en un proyecto de Angular generado con Angular CLI. Bootstrap sigue siendo uno de los frameworks de CSS más usados a nivel mundial, y combinarlo con Angular es una de las primeras dudas que suele surgir cuando se empieza un proyecto nuevo. Vamos a ver dos formas de hacerlo: instalando Bootstrap vía npm, y usando la librería `ng-bootstrap`, que ofrece componentes de Bootstrap reescritos como componentes nativos de Angular.

## Paso 1: Crear el proyecto

Si todavía no tienes Angular CLI instalado:

```bash
npm install -g @angular/cli
```

Creamos un nuevo proyecto:

```bash
ng new mi-app-bootstrap
cd mi-app-bootstrap
```

El CLI te preguntará si quieres agregar Angular routing (recomendable decir que sí) y qué formato de hojas de estilo usar (podemos dejar CSS, ya que Bootstrap se instalará como dependencia aparte).

## Paso 2: Instalar Bootstrap

Instalamos Bootstrap y, opcionalmente, jQuery y Popper.js, que son dependencias necesarias para algunos componentes interactivos de Bootstrap 4 (como los dropdowns, modals o tooltips):

```bash
npm install bootstrap jquery popper.js --save
```

Si estás usando Bootstrap 5, jQuery ya no es necesario, porque los componentes JavaScript fueron reescritos en JavaScript puro.

## Paso 3: Configurar angular.json

Ahora hay que decirle a Angular CLI dónde encontrar los estilos y scripts de Bootstrap. Abrimos `angular.json` y buscamos la sección `architect > build > options`:

```json
"styles": [
  "src/styles.css",
  "node_modules/bootstrap/dist/css/bootstrap.min.css"
],
"scripts": [
  "node_modules/jquery/dist/jquery.min.js",
  "node_modules/popper.js/dist/umd/popper.min.js",
  "node_modules/bootstrap/dist/js/bootstrap.min.js"
]
```

El orden importa: jQuery debe cargarse antes que Popper, y Popper antes que el script principal de Bootstrap, ya que este último depende de los dos anteriores.

## Paso 4: Reiniciar el servidor de desarrollo

Cualquier cambio en `angular.json` requiere reiniciar `ng serve` para que surta efecto:

```bash
ng serve
```

Con esto, ya deberíamos poder usar clases de Bootstrap directamente en nuestros templates:

```html
<div class="container mt-5">
  <div class="alert alert-primary" role="alert">
    ¡Bootstrap está funcionando!
  </div>
  <button class="btn btn-success" data-toggle="modal" data-target="#miModal">
    Abrir modal
  </button>
</div>
```

## Un problema común: componentes JavaScript de Bootstrap y Angular

Aunque las clases CSS de Bootstrap funcionan sin ningún problema en Angular, los componentes que dependen de JavaScript (modals, dropdowns, tooltips, carousels) pueden dar problemas, porque Bootstrap manipula el DOM directamente mientras que Angular espera tener el control total sobre él. Esto puede generar errores extraños, especialmente al destruir y recrear componentes, o simplemente comportamientos inconsistentes entre renders.

Por esta razón, la comunidad de Angular suele recomendar usar `ng-bootstrap` en lugar de la versión "cruda" de Bootstrap con jQuery.

## Alternativa: ng-bootstrap

`ng-bootstrap` es una librería que reimplementa los componentes de Bootstrap como componentes Angular nativos, sin depender de jQuery. Esto la hace mucho más compatible con el ciclo de vida y el sistema de change detection de Angular.

Instalación:

```bash
ng add @ng-bootstrap/ng-bootstrap
```

Este comando, al usar `ng add` (en lugar de `npm install`), no solo instala el paquete, sino que también configura automáticamente los imports necesarios en el `AppModule`.

Con `ng-bootstrap` instalado, ya no necesitamos jQuery ni Popper.js en el `angular.json`; solo mantenemos el CSS de Bootstrap:

```json
"styles": [
  "src/styles.css",
  "node_modules/bootstrap/dist/css/bootstrap.min.css"
]
```

Y podemos usar los componentes directamente en el template, por ejemplo un modal:

```html
<button class="btn btn-primary" (click)="open(content)">Abrir modal</button>

<ng-template #content let-modal>
  <div class="modal-header">
    <h4 class="modal-title">Título del modal</h4>
    <button type="button" class="close" (click)="modal.dismiss()">
      <span>&times;</span>
    </button>
  </div>
  <div class="modal-body">
    Contenido del modal aquí.
  </div>
</ng-template>
```

```ts
import { Component } from '@angular/core';
import { NgbModal } from '@ng-bootstrap/ng-bootstrap';

@Component({
  selector: 'app-root',
  templateUrl: './app.component.html'
})
export class AppComponent {
  constructor(private modalService: NgbModal) {}

  open(content: any) {
    this.modalService.open(content);
  }
}
```

Este enfoque es mucho más "angular", porque el modal se controla con inyección de dependencias y el ciclo de vida de Angular, en lugar de manipular directamente atributos `data-toggle` y `data-target` como en Bootstrap tradicional.

## Personalizando los estilos con Sass

Si en algún momento necesitas personalizar variables de Bootstrap (colores, tipografías, breakpoints), conviene usar la versión Sass en lugar del CSS compilado. Primero, generamos el proyecto (o lo migramos) para usar Sass:

```bash
ng new mi-app-bootstrap --style=scss
```

Y en `src/styles.scss`, en lugar de importar el CSS compilado desde `angular.json`, importamos el Sass fuente de Bootstrap:

```scss
$primary: #ff6b35;
$border-radius: 0.5rem;

@import "~bootstrap/scss/bootstrap";
```

Sobrescribiendo las variables antes del `@import`, Bootstrap las usa para generar todas las clases derivadas (`.btn-primary`, `.text-primary`, `.bg-primary`, etc.), lo que da un control mucho más fino sobre el diseño sin tener que sobrescribir estilos con `!important` después.

## Un ejemplo completo: navbar responsive

Para cerrar, un ejemplo típico de layout con Bootstrap dentro de un componente Angular:

```html
<nav class="navbar navbar-expand-lg navbar-light bg-light">
  <a class="navbar-brand" href="#">Mi App</a>
  <button class="navbar-toggler" type="button" (click)="menuAbierto = !menuAbierto">
    <span class="navbar-toggler-icon"></span>
  </button>
  <div class="collapse navbar-collapse" [class.show]="menuAbierto">
    <ul class="navbar-nav mr-auto">
      <li class="nav-item" *ngFor="let ruta of rutas">
        <a class="nav-link" [routerLink]="ruta.path">{{ ruta.nombre }}</a>
      </li>
    </ul>
  </div>
</nav>
```

Aquí combinamos el binding de clases de Angular (`[class.show]`) con las clases utilitarias de Bootstrap, y usamos `*ngFor` junto con `routerLink` para generar los enlaces de navegación de forma dinámica.

## Conclusión

Integrar Bootstrap con Angular es sencillo cuando solo necesitamos las utilidades CSS, pero se vuelve más delicado en cuanto entran en juego los componentes JavaScript interactivos. Para proyectos pequeños o prototipos, usar Bootstrap directamente vía npm puede ser suficiente. Para proyectos más grandes y mantenibles a largo plazo, `ng-bootstrap` es casi siempre la mejor opción, porque respeta el paradigma de componentes de Angular y evita los conflictos entre la manipulación del DOM de jQuery y el sistema de change detection de Angular.
