Si llevas un tiempo en el desarrollo frontend, conoces el ciclo: aparece un framework, promete resolverlo todo y, unos años después, otro ocupa su lugar. Por eso es lógico mirar con escepticismo cualquier herramienta que se presente como "nueva". Svelte, sin embargo, merece una mirada atenta. No porque sea el último grito, ya que existe desde 2016, sino porque propone una forma **nueva de pensar** cómo se construye una aplicación web. Con la llegada de Svelte 5 y su sistema de *runes*, esa propuesta está más madura que nunca.

En este artículo veremos qué hace distinto a Svelte, cómo se escribe un componente, cómo funciona la reactividad moderna y cuándo tiene sentido elegirlo para tu próximo proyecto.

## Un framework que desaparece

La mayoría de los frameworks populares, como React o Vue, hacen gran parte de su trabajo **en el navegador**. Envías al cliente tu código y, además, una librería que interpreta ese código en tiempo de ejecución, calcula diferencias en un DOM virtual y aplica los cambios necesarios.

Svelte le da la vuelta a esa idea. Es, ante todo, un **compilador**. Durante el *build* toma tus componentes `.svelte` y los transforma en JavaScript optimizado que actualiza el DOM de forma quirúrgica. No hay DOM virtual ni *diffing*. Cuando cambia un valor, el código generado ya sabe exactamente qué nodo tocar.

Rich Harris, su creador, lo resumió con una frase que se ha hecho famosa: Svelte es un framework que "desaparece" en el proceso de compilación. El resultado práctico es este:

- **Paquetes más pequeños.** El runtime que llega al navegador es mínimo.
- **Mejor rendimiento.** Hay menos trabajo en tiempo de ejecución y las actualizaciones son directas.
- **Menos código para escribir.** Como el compilador entiende tu intención, puedes expresarla con menos ceremonia.

## Anatomía de un componente

Un componente de Svelte es un archivo `.svelte` que combina tres piezas que ya conoces: lógica, marcado y estilos.

```svelte
<script>
  let nombre = $state('mundo');
</script>

<h1>¡Hola, {nombre}!</h1>
<input bind:value={nombre} />

<style>
  h1 {
    color: #ff3e00;
    font-family: system-ui, sans-serif;
  }
</style>
```

Hay varias cosas interesantes en estas pocas líneas:

1. **HTML como protagonista.** El marcado no está dentro de una función ni de un `return`. Es HTML con algunas extensiones, como `{nombre}` para interpolar valores.
2. **Enlace bidireccional sencillo.** `bind:value` mantiene sincronizados el input y la variable sin escribir manejadores de eventos.
3. **Estilos con alcance automático.** El CSS del bloque `<style>` solo afecta a este componente. Svelte añade clases únicas al compilar, así que no necesitas CSS-in-JS ni convenciones de nombres para evitar colisiones. Si un selector no se usa, el compilador te avisa.

## Reactividad con *runes*

Svelte 5, publicado en octubre de 2024, introdujo los **runes**: un conjunto de símbolos que empiezan por `$` y le indican al compilador cómo tratar la reactividad. Son explícitos, funcionan igual dentro y fuera de los componentes y se basan en un modelo de *señales* (signals) de grano fino.

### `$state`: estado reactivo

```svelte
<script>
  let contador = $state(0);
</script>

<button onclick={() => contador++}>
  Has hecho clic {contador} {contador === 1 ? 'vez' : 'veces'}
</button>
```

No hay `setContador` ni hooks. Modificas la variable y la interfaz se actualiza. Esto también funciona con objetos y arrays, que se vuelven reactivos de forma profunda:

```svelte
<script>
  let tareas = $state([
    { texto: 'Aprender Svelte', hecha: false }
  ]);

  function agregar(texto) {
    tareas.push({ texto, hecha: false });
  }
</script>
```

Sí, `push` funciona. No necesitas crear copias del array para que Svelte detecte el cambio.

### `$derived`: valores calculados

```svelte
<script>
  let precio = $state(100);
  let cantidad = $state(2);
  let total = $derived(precio * cantidad);
</script>

<p>Total: {total} €</p>
```

`total` se recalcula solo cuando cambian sus dependencias, y Svelte las rastrea automáticamente. No hay que declarar listas de dependencias a mano. Si el cálculo es más complejo, existe `$derived.by(() => { ... })`.

### `$effect`: efectos secundarios

```svelte
<script>
  let tema = $state('claro');

  $effect(() => {
    document.body.dataset.tema = tema;
  });
</script>
```

El efecto se ejecuta después de montar el componente y cada vez que cambia `tema`. Si devuelves una función, Svelte la usa como limpieza. Eso sí, la propia documentación recomienda usar `$effect` con moderación: muchas veces lo que parece un efecto es en realidad un `$derived`.

### `$props`: propiedades del componente

```svelte
<!-- Saludo.svelte -->
<script>
  let { nombre, emoji = '👋' } = $props();
</script>

<p>{emoji} Hola, {nombre}</p>
```

```svelte
<!-- App.svelte -->
<script>
  import Saludo from './Saludo.svelte';
</script>

<Saludo nombre="Ana" />
<Saludo nombre="Luis" emoji="🚀" />
```

Las props se obtienen con desestructuración normal de JavaScript, con valores por defecto incluidos. Si usas TypeScript, puedes tiparlas como cualquier objeto.

## Bloques de control en la plantilla

Svelte ofrece una sintaxis clara para lógica condicional, listas y promesas directamente en el marcado:

```svelte
{#if usuario}
  <p>Bienvenido, {usuario.nombre}</p>
{:else}
  <button onclick={iniciarSesion}>Iniciar sesión</button>
{/if}

<ul>
  {#each tareas as tarea (tarea.id)}
    <li class:hecha={tarea.hecha}>{tarea.texto}</li>
  {:else}
    <li>No hay tareas pendientes 🎉</li>
  {/each}
</ul>

{#await cargarDatos()}
  <p>Cargando…</p>
{:then datos}
  <p>Se recibieron {datos.length} elementos</p>
{:catch error}
  <p>Error: {error.message}</p>
{/await}
```

El bloque `{#await}` es especialmente útil: gestionar los estados de carga, éxito y error de una petición es algo que en otros entornos suele requerir bastante código repetitivo.

## Snippets: reutilizar marcado

Svelte 5 sustituyó los antiguos *slots* por **snippets**, fragmentos de marcado reutilizables que se pueden pasar como props:

```svelte
<!-- Tabla.svelte -->
<script>
  let { filas, fila } = $props();
</script>

<table>
  {#each filas as item}
    <tr>{@render fila(item)}</tr>
  {/each}
</table>
```

```svelte
<Tabla filas={productos}>
  {#snippet fila(p)}
    <td>{p.nombre}</td>
    <td>{p.precio} €</td>
  {/snippet}
</Tabla>
```

El resultado es más flexible y está mejor tipado que el sistema anterior, y se parece mucho al patrón de *render props* de otros frameworks, pero con una sintaxis más limpia.

## Animaciones y transiciones incluidas

Una de las joyas de Svelte es que trae transiciones y animaciones de serie, sin dependencias externas:

```svelte
<script>
  import { fade, fly } from 'svelte/transition';
  let visible = $state(true);
</script>

<button onclick={() => (visible = !visible)}>Alternar</button>

{#if visible}
  <div transition:fly={{ y: 20, duration: 300 }}>
    ¡Aparezco con estilo!
  </div>
{/if}
```

Además de `fade` y `fly`, tienes `slide`, `scale`, `blur`, `draw` para SVG y utilidades como `svelte/motion` para valores animados con física de muelle.

## SvelteKit: de componentes a aplicaciones

Svelte por sí solo es una herramienta para construir componentes. Para aplicaciones completas existe **SvelteKit**, el meta-framework oficial, que cumple un papel similar al de Next.js o Nuxt. Incluye:

- **Enrutamiento basado en archivos.** Cada carpeta dentro de `src/routes` es una ruta.
- **Renderizado flexible.** SSR, generación estática (SSG) o SPA, configurable por ruta.
- **Carga de datos en servidor** mediante funciones `load` en archivos `+page.server.js`.
- **Form actions** para gestionar formularios con mejora progresiva, de modo que funcionan incluso sin JavaScript.
- **Adaptadores** para desplegar en Node, Vercel, Netlify, Cloudflare y otras plataformas.

Un ejemplo mínimo de carga de datos:

```js
// src/routes/blog/+page.server.js
export async function load({ fetch }) {
  const res = await fetch('/api/posts');
  return { posts: await res.json() };
}
```

```svelte
<!-- src/routes/blog/+page.svelte -->
<script>
  let { data } = $props();
</script>

<h1>Blog</h1>
{#each data.posts as post}
  <article>
    <h2><a href="/blog/{post.slug}">{post.titulo}</a></h2>
  </article>
{/each}
```

## Cómo empezar

Crear un proyecto nuevo es cuestión de segundos con la CLI oficial:

```bash
npx sv create mi-app
cd mi-app
npm install
npm run dev
```

El asistente te preguntará si quieres TypeScript, ESLint, Prettier, Vitest, Playwright, Tailwind y otras integraciones. En unos instantes tendrás un servidor de desarrollo con recarga en caliente gracias a Vite.

Si prefieres experimentar sin instalar nada, el [playground oficial](https://svelte.dev/playground) y el [tutorial interactivo](https://svelte.dev/tutorial) son de lo mejor que existe en el ecosistema frontend.

## ¿Cuándo elegir Svelte?

Svelte brilla especialmente en estos escenarios:

- **Proyectos donde el rendimiento y el peso importan:** sitios de contenido, aplicaciones para móviles con conexiones lentas, widgets embebibles.
- **Equipos que valoran la productividad:** hay menos código repetitivo y una curva de aprendizaje suave para quien ya domina HTML, CSS y JavaScript.
- **Visualizaciones de datos y aplicaciones interactivas:** no en vano, Svelte nació en la redacción gráfica de *The New York Times* y *The Guardian*.

También conviene ser honestos con sus limitaciones. Su ecosistema de librerías es más pequeño que el de React y la oferta de empleo, aunque crece, sigue siendo menor. Si tu proyecto depende de una librería muy concreta que solo existe para React, es un factor a tener en cuenta.

## Conclusión

Svelte demuestra que se pueden construir interfaces modernas sin cargar al navegador con el peso de un framework entero. Su enfoque basado en compilación, la reactividad explícita y de grano fino de Svelte 5, los estilos con alcance automático y un meta-framework sólido como SvelteKit lo convierten en una opción seria para casi cualquier tipo de aplicación web.

Si no lo has probado, dedícale una tarde al tutorial oficial. Es muy posible que, al volver a tu framework habitual, empieces a preguntarte por qué escribes tanto código para hacer lo mismo.
