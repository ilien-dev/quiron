runtime: shift timeHistogram buckets and allow negative durations

timeHistogram currently records durations as non-negative values and
folds anything below zero into the lowest bucket. That loses
information for callers that compute differences between timestamps,
which can legitimately be negative, such as when comparing values
captured on different goroutines or measuring the delta between two
sampled events.

This change shifts the bucket layout so the histogram's range begins
below zero. The bucket index is computed with a fixed offset, so
existing non-negative buckets keep their boundaries relative to their
exponent and sub-bucket, while negative durations land in dedicated
lower buckets instead of being clamped to zero.

Code that reads the histogram must account for the shifted indices.
The Float64Histogram exported through runtime/metrics reflects the
new bucket boundaries, including the negative range.

Callers that record only non-negative durations see no functional
change beyond the index offset.
