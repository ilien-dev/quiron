upload-pack.c: increase output buffer size

When serving a fetch, upload-pack reads the pack stream produced by
pack-objects and relays it to the client, wrapping each chunk in a
side-band packet. The buffer used for this relay is only 8191 bytes,
so a large pack is split into many small packets.

Each packet carries its own pkt-line header and band designator, and
each one costs a separate read from pack-objects and a separate write
to the client. For big clones this overhead adds up, both in syscalls
and in framing bytes on the wire. It also makes the server do more
work per byte served than necessary.

The side-band-64k protocol allows packets of up to 65520 bytes,
including the 4-byte length header and the 1-byte band designator.
Raise the buffer size so that we can fill a packet to that limit when
the data is available, and keep the existing smaller limit for clients
that only speak plain side-band, since they cannot accept larger
packets.

The protocol on the wire is unchanged; clients simply receive fewer,
larger packets. The memory cost is a single fixed-size buffer per
upload-pack process, which is negligible.
