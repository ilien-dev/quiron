# How to build a full stack NFT marketplace - V2 (2022)

An NFT marketplace is a good project for learning Web3, because you touch almost everything: smart contracts, wallet auth, decentralized storage and a modern frontend.

We'll build a full stack NFT marketplace where users can:

- Connect an Ethereum wallet
- Mint NFTs with images and metadata
- List NFTs for sale
- Browse available NFTs
- Purchase NFTs
- View owned and created assets

The stack is Solidity, Hardhat, Polygon, Next.js, ethers.js and IPFS.

> This tutorial uses the Web3 tooling available in 2022. Some package APIs may differ in newer versions.

There are three main pieces. The smart contract creates the NFTs and keeps track of the listings, and it also handles sales. IPFS holds the NFT images and metadata. And the Next.js app is the interface that the user actually sees, and it's what talks to the blockchain.

The NFT itself is a standard ERC-721 token. The listings live in the smart contract, so there's no traditional backend or database to run.

## Setting up

Create a new Next.js app:

```bash
npx create-next-app nft-marketplace
cd nft-marketplace
```

Install the dependencies:

```bash
npm install ethers@5 web3modal axios
npm install ipfs-http-client
npm install --save-dev hardhat @nomiclabs/hardhat-ethers
npm install @openzeppelin/contracts
```

Then initialize Hardhat:

```bash
npx hardhat
```

Pick **Create a basic sample project** when it asks. You should now have `contracts`, `scripts` and `test` folders next to the Next.js app.

## The smart contract

Create `contracts/NFTMarketplace.sol`:

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.4;

import "@openzeppelin/contracts/utils/Counters.sol";
import "@openzeppelin/contracts/token/ERC721/extensions/ERC721URIStorage.sol";
import "@openzeppelin/contracts/security/ReentrancyGuard.sol";

contract NFTMarketplace is ERC721URIStorage, ReentrancyGuard {
    using Counters for Counters.Counter;

    Counters.Counter private tokenIds;
    Counters.Counter private soldItems;

    uint256 public listingPrice = 0.025 ether;
    address payable private marketplaceOwner;

    struct MarketItem {
        uint256 tokenId;
        address payable seller;
        address payable owner;
        uint256 price;
        bool sold;
    }

    mapping(uint256 => MarketItem) private marketItems;

    event MarketItemCreated(
        uint256 indexed tokenId,
        address seller,
        address owner,
        uint256 price,
        bool sold
    );

    constructor() ERC721("Marketplace Token", "MKT") {
        marketplaceOwner = payable(msg.sender);
    }

    function createToken(
        string memory tokenURI,
        uint256 price
    ) public payable returns (uint256) {
        tokenIds.increment();
        uint256 newTokenId = tokenIds.current();

        _mint(msg.sender, newTokenId);
        _setTokenURI(newTokenId, tokenURI);
        createMarketItem(newTokenId, price);

        return newTokenId;
    }

    function createMarketItem(
        uint256 tokenId,
        uint256 price
    ) private {
        require(price > 0, "Price must be greater than zero");
        require(
            msg.value == listingPrice,
            "Submit the required listing price"
        );

        marketItems[tokenId] = MarketItem(
            tokenId,
            payable(msg.sender),
            payable(address(this)),
            price,
            false
        );

        _transfer(msg.sender, address(this), tokenId);

        emit MarketItemCreated(
            tokenId,
            msg.sender,
            address(this),
            price,
            false
        );
    }
}
```

When someone lists an NFT, it's transferred to the marketplace contract, which holds it in escrow until somebody buys it.

Next, the function that handles a purchase:

```solidity
function createMarketSale(uint256 tokenId) public payable nonReentrant {
    MarketItem storage item = marketItems[tokenId];

    require(msg.value == item.price, "Submit the asking price");
    require(!item.sold, "Item has already been sold");

    item.seller.transfer(msg.value);
    transferFrom(address(this), msg.sender, tokenId);

    item.owner = payable(msg.sender);
    item.sold = true;
    soldItems.increment();

    marketplaceOwner.transfer(listingPrice);
}
```

`nonReentrant` guards against reentrancy attacks while the money and the token change hands.

We also need a way to load the NFTs that haven't sold yet:

```solidity
function fetchMarketItems() public view returns (MarketItem[] memory) {
    uint256 totalItems = tokenIds.current();
    uint256 unsoldCount = totalItems - soldItems.current();
    uint256 index = 0;

    MarketItem[] memory items = new MarketItem[](unsoldCount);

    for (uint256 i = 1; i <= totalItems; i++) {
        if (marketItems[i].owner == address(this)) {
            items[index] = marketItems[i];
            index++;
        }
    }

    return items;
}
```

You can write similar view functions for the NFTs a user owns and the ones they created. Here's the one for owned NFTs:

```solidity
function fetchMyNFTs() public view returns (MarketItem[] memory) {
    uint256 totalItems = tokenIds.current();
    uint256 itemCount = 0;
    uint256 index = 0;

    for (uint256 i = 1; i <= totalItems; i++) {
        if (marketItems[i].owner == msg.sender) {
            itemCount++;
        }
    }

    MarketItem[] memory items = new MarketItem[](itemCount);

    for (uint256 i = 1; i <= totalItems; i++) {
        if (marketItems[i].owner == msg.sender) {
            items[index] = marketItems[i];
            index++;
        }
    }

    return items;
}
```

## Compile and deploy locally

Update `hardhat.config.js`:

```javascript
require("@nomiclabs/hardhat-ethers");

module.exports = {
  solidity: "0.8.4",
  networks: {
    hardhat: {
      chainId: 1337,
    },
  },
};
```

Compile the contract:

```bash
npx hardhat compile
```

Create `scripts/deploy.js`:

```javascript
async function main() {
  const Marketplace = await ethers.getContractFactory("NFTMarketplace");
  const marketplace = await Marketplace.deploy();

  await marketplace.deployed();

  console.log("Marketplace deployed to:", marketplace.address);
}

main()
  .then(() => process.exit(0))
  .catch((error) => {
    console.error(error);
    process.exit(1);
  });
```

Start a local blockchain:

```bash
npx hardhat node
```

In another terminal, deploy the contract:

```bash
npx hardhat run scripts/deploy.js --network localhost
```

Copy the address it prints, because the frontend needs it.

## Connecting the frontend

Create `config.js` in the project root:

```javascript
export const marketplaceAddress =
  "YOUR_DEPLOYED_CONTRACT_ADDRESS";
```

Hardhat puts the contract ABI in the `artifacts` folder. Import it wherever the frontend needs a contract instance. For reading, a JSON-RPC provider is enough:

```javascript
import { ethers } from "ethers";
import NFTMarketplace from "./artifacts/contracts/NFTMarketplace.sol/NFTMarketplace.json";
import { marketplaceAddress } from "./config";

const provider = new ethers.providers.JsonRpcProvider(
  "http://127.0.0.1:8545"
);

const contract = new ethers.Contract(
  marketplaceAddress,
  NFTMarketplace.abi,
  provider
);
```

To send a transaction you need a signer from the user's wallet, so here's a small helper that does that:

```javascript
import Web3Modal from "web3modal";

async function getSignedContract() {
  const web3Modal = new Web3Modal();
  const connection = await web3Modal.connect();
  const provider = new ethers.providers.Web3Provider(connection);
  const signer = provider.getSigner();

  return new ethers.Contract(
    marketplaceAddress,
    NFTMarketplace.abi,
    signer
  );
}
```

Web3Modal shows the wallet picker, and ethers.js wraps whichever wallet the user picked as a signer.

## Uploading to IPFS

An NFT's `tokenURI` usually points to a JSON file with its name, description and image URL. We'll put the image and that metadata file on IPFS.

Set up an IPFS client with whatever pinning service you want to use:

```javascript
import { create as createIPFSClient } from "ipfs-http-client";

const client = createIPFSClient({
  url: "YOUR_IPFS_API_ENDPOINT",
  headers: {
    authorization: "YOUR_AUTHORIZATION_HEADER",
  },
});
```

Don't put a private IPFS API secret in browser code in production. Do the uploads from a server-side API route, or use a provider that lets clients upload with safely scoped access.

Uploading the image the user picked:

```javascript
async function uploadImage(event) {
  const file = event.target.files[0];
  if (!file) return;

  const result = await client.add(file);
  const imageUrl = `https://ipfs.io/ipfs/${result.path}`;

  setFileUrl(imageUrl);
}
```

And the metadata:

```javascript
async function createMetadata(name, description, image) {
  const data = JSON.stringify({
    name,
    description,
    image,
  });

  const result = await client.add(data);
  return `https://ipfs.io/ipfs/${result.path}`;
}
```

## Minting, listing and buying

The mint form asks for a name, a description, a price and an image. Once the uploads are done, call `createToken`:

```javascript
async function createNFT() {
  const metadataUrl = await createMetadata(
    formInput.name,
    formInput.description,
    fileUrl
  );

  const contract = await getSignedContract();
  const price = ethers.utils.parseUnits(formInput.price, "ether");
  const listingPrice = await contract.listingPrice();

  const transaction = await contract.createToken(
    metadataUrl,
    price,
    {
      value: listingPrice,
    }
  );

  await transaction.wait();
}
```

That one call does two things on chain. It mints the token and puts it into the marketplace's escrow.

Validate the form before you submit it. If the image is missing or the price is invalid, the user should never get as far as the wallet confirmation.

To show the marketplace, load the unsold items. Then, for each one, get the token's metadata:

```javascript
async function loadNFTs() {
  const data = await contract.fetchMarketItems();

  const items = await Promise.all(
    data.map(async (item) => {
      const tokenUri = await contract.tokenURI(item.tokenId);
      const metadata = await axios.get(tokenUri);

      return {
        tokenId: item.tokenId.toNumber(),
        seller: item.seller,
        owner: item.owner,
        price: ethers.utils.formatUnits(
          item.price.toString(),
          "ether"
        ),
        image: metadata.data.image,
        name: metadata.data.name,
        description: metadata.data.description,
      };
    })
  );

  setNfts(items);
}
```

Then render them with plain React components:

```jsx
{nfts.map((nft) => (
  <article key={nft.tokenId}>
    <img src={nft.image} alt={nft.name} />
    <h2>{nft.name}</h2>
    <p>{nft.description}</p>
    <strong>{nft.price} ETH</strong>
    <button onClick={() => buyNFT(nft)}>Buy</button>
  </article>
))}
```

Buying calls `createMarketSale` and sends exactly the asking price:

```javascript
async function buyNFT(nft) {
  const contract = await getSignedContract();
  const price = ethers.utils.parseUnits(nft.price, "ether");

  const transaction = await contract.createMarketSale(
    nft.tokenId,
    {
      value: price,
    }
  );

  await transaction.wait();
  await loadNFTs();
}
```

Once the transaction is confirmed, the seller gets paid and the buyer gets the NFT. The item also drops out of the listings.

## Deploy to Polygon

A local chain is great for testing quickly, but a public marketplace has to run on a shared network. Polygon has low transaction fees and works with the Ethereum tooling we've been using.

Add Polygon's test network to your Hardhat config, with an RPC provider and a wallet to deploy from:

```javascript
require("dotenv").config();

module.exports = {
  solidity: "0.8.4",
  networks: {
    polygonTestnet: {
      url: process.env.POLYGON_RPC_URL,
      accounts: [process.env.PRIVATE_KEY],
    },
  },
};
```

Keep the credentials in `.env`:

```text
POLYGON_RPC_URL=YOUR_RPC_URL
PRIVATE_KEY=YOUR_PRIVATE_KEY
```

Never commit this file. Add it to `.gitignore`, put some test tokens in the deployment wallet, and deploy:

```bash
npx hardhat run scripts/deploy.js --network polygonTestnet
```

Swap the local contract address in `config.js` for the new one. Your wallet and the frontend both have to be on that same network too.

## Before real money is involved

This is fine for learning, but a production contract needs a lot more work. Before it handles anything of real value:

- Write tests for minting, buying, permissions, and failed transactions.
- Settle on a clear fee and royalty model.
- Add events for every important state transition.
- Avoid unbounded loops as the collection grows.
- Consider indexing events with a service such as The Graph.
- Pin IPFS content through multiple reliable providers.
- Handle rejected transactions and network mismatches in the UI.
- Get an independent security audit of the contract.

Upgradable contracts can be useful, but they bring their own governance and security tradeoffs. An immutable contract is often easier for users to reason about.

From here you could add auctions, creator royalties, collection pages, search, activity feeds or better wallet support.
