# Using FastImage to get image dimensions in Ruby

Applications that accept image URLs often need the width and height before downloading or processing the whole file. Maybe you want to validate a remote image and reject files that are too small. Maybe you need the aspect ratio, or want to reserve space for the image in a layout.

The `fastimage` gem does exactly this. It reads only the part of the file it needs to find the size, so it's much more efficient than downloading the complete image and opening it with an image-processing library.

## Installing it

Add the gem to your `Gemfile`:

```ruby
gem "fastimage"
```

Then install it:

```bash
bundle install
```

Or install it directly:

```bash
gem install fastimage
```

If you aren't using Bundler's automatic loading, require it:

```ruby
require "fastimage"
```

## Getting the size

The main call is `FastImage.size`. Give it a URL and you get back an array with the width and height:

```ruby
url = "https://example.com/images/header.jpg"

width, height = FastImage.size(url)

puts "Width: #{width}px"
puts "Height: #{height}px"
```

For a 1200 by 630 image you get:

```ruby
[1200, 630]
```

This works because common image formats store their dimensions in metadata near the beginning of the file. FastImage requests enough data to locate that information and stops there.

You can get the format too:

```ruby
type = FastImage.type(url)

puts type
# => :jpeg
```

Supported formats include JPEG, PNG, GIF, BMP, TIFF, ICO, WebP and SVG.

It isn't limited to remote URLs either. Files stored on disk work the same way, so your code gets one consistent interface:

```ruby
width, height = FastImage.size("public/uploads/avatar.png")

puts "#{width}x#{height}"
```

Once you have the two numbers, the aspect ratio is easy:

```ruby
width, height = FastImage.size(url)

if width && height
  aspect_ratio = width.to_f / height
  puts aspect_ratio.round(2)
end
```

The `to_f` matters. It makes the intent clear and avoids integer division surprises in older Ruby versions.

You can also sort images by shape, which is handy when you pick thumbnails or decide how an image should sit in a responsive layout:

```ruby
orientation =
  if width > height
    :landscape
  elsif height > width
    :portrait
  else
    :square
  end
```

## When it fails

Remote resources are unreliable. A URL can be unavailable or slow. It can also point at something that isn't a supported image. By default `FastImage.size` just returns `nil` when it can't get the size:

```ruby
dimensions = FastImage.size(url)

if dimensions
  width, height = dimensions
  puts "#{width}x#{height}"
else
  puts "Unable to read image dimensions"
end
```

If you'd rather get exceptions, turn on `raise_on_failure`:

```ruby
begin
  width, height = FastImage.size(
    url,
    timeout: 5,
    raise_on_failure: true
  )

  puts "#{width}x#{height}"
rescue FastImage::ImageFetchFailure => e
  warn "Could not fetch image: #{e.message}"
rescue FastImage::UnknownImageType => e
  warn "Unsupported image: #{e.message}"
end
```

Set the timeout. Without it a slow server can tie up your application indefinitely.

A small helper turns this into a check you can reuse:

```ruby
def large_enough?(url, minimum_width:, minimum_height:)
  width, height = FastImage.size(url, timeout: 5)

  width >= minimum_width && height >= minimum_height
rescue TypeError
  false
end
```

And you call it like this:

```ruby
large_enough?(
  "https://example.com/photo.jpg",
  minimum_width: 800,
  minimum_height: 600
)
```

One thing to keep in mind with user-supplied URLs: the request is made by your server. Restrict the allowed hosts or network destinations, or you've opened yourself up to server-side request forgery.

FastImage won't resize, optimize or transform an image. It gets you the size and the format, and if that's all you need, you avoid the cost and complexity of a full image-processing pipeline.
