# A Semi Technical Explainer of All Known Zoom Issues

Zoom has become one of the most widely used pieces of software on the planet, and with that scale has come an enormous amount of scrutiny. Over the past several months, a steady stream of security and privacy issues has come out, some minor, some genuinely alarming. It's easy to lose track of what's actually serious and what's overblown internet panic. This post tries to lay out, in reasonably plain language, the major issues that have been reported, what they actually mean, and what Zoom has done (or hasn't done) about each one.

## The "End-to-End Encryption" Claim

For a long time, Zoom marketed its calls as "end-to-end encrypted." This turned out not to be accurate in the way most security-conscious users understand the term. True end-to-end encryption means that only the participants in a call can decrypt the content, and the service provider itself has no ability to access it. Zoom's actual implementation used TLS to encrypt data in transit between clients and Zoom's servers, meaning Zoom itself technically had the ability to access unencrypted content passing through its infrastructure. That's a meaningfully different security model from true end-to-end encryption, and Zoom eventually walked back the marketing language and committed to building genuine end-to-end encryption as an opt-in feature.

## Routing Traffic Through China

Security researchers discovered that some Zoom calls, including calls between participants entirely outside of China, were being routed through servers located in China at various points. For any organization concerned about jurisdictional data access, particularly given China's legal framework around data requests, this was a significant red flag. Zoom acknowledged the issue, attributed it to a capacity-related mistake during a period of rapidly scaling infrastructure, and said it had fixed the routing logic and added safeguards to prevent similar geographic misrouting going forward.

## Zoombombing

Perhaps the most visible issue to ordinary users was "Zoombombing," where uninvited people would join public or under-secured meetings and disrupt them, sometimes with offensive content. This wasn't really a vulnerability in the traditional sense. It was largely a consequence of default settings that made meetings too easy to find and join without proper authentication, combined with the sheer number of new, non-technical users who suddenly needed to run video calls and didn't know what settings to change. Zoom responded by changing defaults to enable passwords and waiting rooms automatically for many account types, and added more visible controls for hosts to lock meetings, remove participants, and restrict screen sharing.

## The macOS Webcam Vulnerability

Before the pandemic-driven surge in Zoom's popularity, a researcher disclosed a vulnerability in the Mac client where Zoom had installed a local web server on users' machines, without clear consent, specifically to bypass a Safari security prompt that would otherwise ask users to confirm before joining a call. The unintended side effect was that any malicious website could potentially force a user's webcam to activate without permission, simply by crafting a link that interacted with this local server. Even more concerning, this local server would persist and silently reinstall Zoom even after a user had fully uninstalled the application. Zoom eventually removed the local web server entirely after public pressure, but the episode raised serious questions about installing hidden local services without explicit user knowledge.

## Windows UNC Path Injection

Zoom's chat feature was found to convert Windows network paths, formatted as UNC paths, into clickable links. Clicking one of these links could cause Windows to automatically attempt to authenticate to a remote server using the victim's login credentials, potentially leaking the user's Windows username and a hashed version of their password to an attacker-controlled server. In some circumstances, clicking such a link could also allow execution of arbitrary commands on the victim's machine. This is a well-known class of vulnerability in Windows applications that render untrusted text as clickable links without proper sanitization, and Zoom patched the specific issue after disclosure.

## Data Sharing With Facebook

Zoom's iOS app was found to be sending analytics data to Facebook every time the app was opened, regardless of whether the user had a Facebook account or had ever logged in through Facebook. This happened through the Facebook SDK that Zoom had integrated to support a "Login with Facebook" feature, but the SDK was collecting and transmitting device information for all users, not just those using that specific login option. Zoom removed the Facebook SDK from its iOS app shortly after this was reported.

## Attention Tracking Feature

Zoom included a feature that let meeting hosts see an indicator if a participant's Zoom window lost focus for more than a set period of time, intended as a way for hosts to gauge whether attendees were paying attention during a presentation. Privacy advocates raised concerns about this kind of monitoring, especially in workplace and educational contexts where power imbalances make it difficult for participants to object. Zoom eventually removed the attention tracking feature entirely in response to the criticism.

## Vulnerabilities in the Meeting ID System

Researchers demonstrated that Zoom's meeting IDs, a relatively short numeric string, could in some cases be guessed or brute-forced, potentially allowing unauthorized users to stumble into meetings they weren't invited to, particularly meetings that weren't password protected. This overlaps conceptually with the Zoombombing issue but is a distinct underlying weakness in how meetings were identified and secured by default. Enabling passwords and waiting rooms by default substantially mitigates this risk, which is part of why Zoom made those settings mandatory for many types of accounts.

## Zoom's Response as a Pattern

Looking at these issues together, a pattern emerges. Many of Zoom's problems stemmed less from a single catastrophic flaw and more from a company that scaled from roughly ten million daily meeting participants to hundreds of millions in a matter of weeks, while carrying design decisions and default settings that were made when the product's primary users were business customers running smaller, more controlled meetings. To its credit, Zoom's response to nearly every one of these disclosures followed a similar pattern: acknowledge the issue publicly, ship a fix relatively quickly, and in several cases, proactively change defaults for the broader user base rather than just patching the specific reported flaw. The company also announced a freeze on new feature development for a period specifically to focus engineering resources on security and privacy issues, and brought in outside security expertise to review its practices.

## Should You Still Use Zoom?

This is ultimately a risk tolerance question that depends heavily on your specific use case. For casual personal calls, most of these issues are low practical risk, especially after the fixes and default changes that have shipped. For organizations handling sensitive information, healthcare data, legal proceedings, or anything with strict compliance requirements, it's worth evaluating Zoom's current security posture carefully against your specific threat model, checking that passwords and waiting rooms are enabled, and staying current with client updates, since several of these issues were only exploitable on outdated versions of the software.

## Wrapping Up

None of this makes Zoom uniquely bad among video conferencing tools. Rapid scale tends to expose exactly this kind of issue in any software, and plenty of comparable platforms have had their own share of security problems that simply received less attention because they didn't experience the same meteoric rise in usage. What matters most going forward is whether the pattern of quick, transparent fixes continues, and whether the promised end-to-end encryption and continued security investment actually materialize in a way users and organizations can independently verify.
