# How to Combine Rails's Ajax Support and Stimulus

Rails has had built-in Ajax helpers for a long time. With `rails-ujs`, you can add `remote: true` to a link or form and Rails will submit it over XHR instead of a full page reload. It's simple, it's convenient, and for years it's been the default way to sprinkle interactivity into a Rails app.

Stimulus, on the other hand, is a small JavaScript framework from Basecamp that's designed to work with the HTML you already have. It connects JavaScript behavior to elements through `data-` attributes, without taking over rendering.

On their own, both are great. But they overlap in interesting ways, and it's not always obvious how to use them together. In this post, I'll show how to handle Rails's Ajax events from Stimulus controllers, so you can keep server-rendered forms and links while adding richer client-side behavior.

## The setup

I'm assuming a Rails app with Webpacker (or jsbundling) and Stimulus installed. If you're starting from scratch:

```bash
rails new ajax_stimulus --webpack=stimulus
```

And make sure `rails-ujs` is started in your pack:

```javascript
// app/javascript/packs/application.js
import Rails from '@rails/ujs';
Rails.start();

import 'controllers';
```

A quick note: newer Rails versions default to Turbo instead of `rails-ujs`. Everything in this post applies to apps that use `rails-ujs`, which is still very common in existing codebases.

## How rails-ujs Ajax works

When you write something like this:

```erb
<%= form_with model: @comment, local: false do |form| %>
  <%= form.text_area :body %>
  <%= form.submit "Post" %>
<% end %>
```

(Or `remote: true` in older versions.) `rails-ujs` intercepts the submit, sends the request via XHR, and fires a series of custom DOM events on the form:

| Event | When it fires |
|-------|---------------|
| `ajax:before` | Before anything happens; can cancel |
| `ajax:beforeSend` | Before the request is sent; can cancel |
| `ajax:send` | When the request is sent |
| `ajax:stopped` | When the request was cancelled |
| `ajax:success` | On a successful response |
| `ajax:error` | On an error response |
| `ajax:complete` | After success or error |

The key detail: in `rails-ujs`, the event data lives in `event.detail`, which is an array. For `ajax:success` and `ajax:error`, it looks like `[response, status, xhr]`.

These are regular DOM events, and they bubble. That's what makes them work so nicely with Stimulus.

## Listening to Ajax events with Stimulus actions

Stimulus actions can listen to any DOM event, including custom ones. The syntax is `event->controller#method`. So we can wire up Rails's Ajax events directly in the markup:

```erb
<%= form_with model: @comment, local: false,
      data: {
        controller: "comment-form",
        action: "ajax:success->comment-form#onSuccess ajax:error->comment-form#onError"
      } do |form| %>
  <%= form.text_area :body, data: { comment_form_target: "body" } %>
  <%= form.submit "Post", data: { comment_form_target: "submit" } %>
  <div data-comment-form-target="errors"></div>
<% end %>
```

And the controller:

```javascript
// app/javascript/controllers/comment_form_controller.js
import { Controller } from 'stimulus';

export default class extends Controller {
  static targets = ['body', 'submit', 'errors'];

  onSuccess(event) {
    const [data, status, xhr] = event.detail;
    this.bodyTarget.value = '';
    this.errorsTarget.innerHTML = '';
  }

  onError(event) {
    const [data, status, xhr] = event.detail;
    this.errorsTarget.innerHTML = xhr.response;
  }
}
```

That's the core pattern. Rails handles the request, Stimulus handles the response.

## Handling the response body

What `data` contains depends on the response's content type. If the server returns JSON, `rails-ujs` parses it for you. If it returns HTML, you get a parsed `Document`. For many cases, the simplest thing is to use `xhr.response` to get the raw text.

Let's say our controller returns a rendered partial on success:

```ruby
# app/controllers/comments_controller.rb
def create
  @comment = @post.comments.build(comment_params)

  if @comment.save
    render partial: 'comments/comment', locals: { comment: @comment }, status: :created
  else
    render partial: 'comments/errors', locals: { comment: @comment }, status: :unprocessable_entity
  end
end
```

Now the Stimulus controller can insert the new comment into the list:

```javascript
export default class extends Controller {
  static targets = ['body', 'errors'];
  static values = { listId: String };

  onSuccess(event) {
    const [, , xhr] = event.detail;
    const list = document.getElementById(this.listIdValue);
    list.insertAdjacentHTML('beforeend', xhr.response);
    this.bodyTarget.value = '';
    this.errorsTarget.innerHTML = '';
  }

  onError(event) {
    const [, , xhr] = event.detail;
    this.errorsTarget.innerHTML = xhr.response;
  }
}
```

With the value passed in from the markup:

```erb
data: { controller: "comment-form", comment_form_list_id_value: "comments", ... }
```

The server still renders all the HTML, which keeps your templates in one place. Stimulus just decides where it goes.

## Loading states

A common need is disabling the submit button and showing a spinner while the request is in flight. We can use `ajax:send` and `ajax:complete` for that:

```erb
action: "ajax:send->comment-form#onSend ajax:complete->comment-form#onComplete ajax:success->comment-form#onSuccess ajax:error->comment-form#onError"
```

```javascript
onSend() {
  this.submitTarget.disabled = true;
  this.element.classList.add('is-loading');
}

onComplete() {
  this.submitTarget.disabled = false;
  this.element.classList.remove('is-loading');
}
```

Worth knowing: `rails-ujs` also supports `data-disable-with` on submit buttons, which handles the disable/re-enable for you. Use whichever fits; the Stimulus version is handy when you need to do more than just toggle the button.

## Triggering Ajax from Stimulus

Sometimes you want to kick off a request from JavaScript instead of from a form submit. For example, auto-saving a draft after the user stops typing. `rails-ujs` exposes `Rails.ajax`, which handles CSRF tokens for you:

```javascript
import { Controller } from 'stimulus';
import Rails from '@rails/ujs';

export default class extends Controller {
  static values = { url: String };

  connect() {
    this.timeout = null;
  }

  save() {
    clearTimeout(this.timeout);
    this.timeout = setTimeout(() => {
      Rails.ajax({
        url: this.urlValue,
        type: 'PATCH',
        data: new FormData(this.element),
        success: () => this.showSaved(),
        error: () => this.showError(),
      });
    }, 500);
  }

  showSaved() { /* ... */ }
  showError() { /* ... */ }
}
```

```erb
<%= form_with model: @draft, data: {
      controller: "autosave",
      autosave_url_value: draft_path(@draft),
      action: "input->autosave#save"
    } do |form| %>
```

Alternatively, if you want to trigger the *form's* normal remote submission and keep all the `ajax:*` events firing, use `Rails.fire`:

```javascript
Rails.fire(this.element, 'submit');
```

Calling `this.element.submit()` directly won't work here, because it bypasses the submit event entirely and does a full page submission. `Rails.fire` dispatches the event so `rails-ujs` can intercept it.

## Listening on a parent element

Because Ajax events bubble, you don't have to put the controller on the form itself. You can put it on a container and catch events from any remote form or link inside it:

```erb
<div data-controller="comments"
     data-action="ajax:success->comments#refresh">
  <% @comments.each do |comment| %>
    <%= link_to "Delete", comment, method: :delete, remote: true %>
  <% end %>
</div>
```

```javascript
refresh(event) {
  const link = event.target;
  link.closest('.comment').remove();
}
```

`event.target` tells you which form or link actually triggered the request. This is great for lists where you'd otherwise need a controller instance per item.

## Why not just use fetch?

You absolutely can use `fetch` in Stimulus controllers, and for new apps many people do. But there are reasons to lean on `rails-ujs` when it's already there:

- **CSRF tokens are handled automatically.**
- **Server-rendered forms work without JavaScript.** If JS fails, the form still submits normally.
- **`data-confirm`, `data-disable-with`, and `method:` links** keep working as usual.
- **Your markup stays declarative.** Most of the behavior is visible right in the HTML.

Stimulus then fills in the gaps, handling responses, managing UI state, and coordinating between elements, without you having to rewrite the request logic.

## Wrapping up

Rails's Ajax helpers and Stimulus are a surprisingly good match. The recipe is:

1. Let `rails-ujs` submit forms and links remotely.
2. Listen to `ajax:*` events with Stimulus actions.
3. Pull the response out of `event.detail` and update the DOM.
4. Use `Rails.ajax` or `Rails.fire` when you need to trigger requests from JavaScript.

You keep the simplicity of server-rendered HTML and the Rails conventions you already know, and Stimulus gives you a clean, organized place to put the behavior that doesn't belong on the server. If you later move to Turbo, a lot of these patterns carry over too, just with `turbo:submit-end` and friends instead of `ajax:success`.
