# Project and Porfolio Ideas 2020

If you're learning to code, or trying to break into your first developer job, you've probably heard the advice a hundred times: build a portfolio. The problem is that most portfolio advice stops right there, leaving you staring at a blank editor with no idea what to actually build. So instead of another generic "build projects" pep talk, here's a list of concrete project ideas you can start this year, along with why each one is worth your time.

## A Personal Website

This one feels obvious, but it's obvious for a reason. A personal site is the single most flexible project you can build, because it's simultaneously a portfolio, a resume, a blog, and a demonstration of your front-end skills all in one place. Don't overthink the design. A clean, fast, readable site beats a flashy one that takes eight seconds to load. Include links to your other projects, a short bio, and a way to contact you, and you're most of the way there.

## A Clone of a Tool You Actually Use

Building a clone of something you already use daily, whether that's a to-do app, a note-taking tool, or a simple version of your favorite productivity app, is a great exercise because you already understand the requirements intimately. You don't have to guess what features matter, because you're your own user. This makes it much easier to scope the project realistically and actually finish it, instead of spiraling into feature creep on something you don't fully understand yourself.

## An API-Backed Data Project

Pick a public API, whether it's weather data, a movie database, sports statistics, or anything else that interests you, and build something that consumes it in an interesting way. This is a great opportunity to practice working with asynchronous requests, handling loading and error states, and thinking about how to structure UI around data you don't control. Bonus points if you add some kind of filtering, sorting, or visualization on top of the raw data instead of just displaying it as-is.

## A CLI Tool

Not every portfolio project needs a UI. Building a small command-line tool that solves a real annoyance in your own workflow, like renaming a batch of files, converting file formats, or scaffolding boilerplate, is a great way to demonstrate that you can write clean, practical code without leaning on a framework to do the heavy lifting for you. It also shows range, since most junior portfolios are stuffed entirely with web apps.

## An Open Source Contribution

This isn't a project you build from scratch, but it belongs on this list anyway. Find an open source project you actually use, look through its open issues for something labeled "good first issue," and submit a real pull request. This demonstrates something a solo project can't: that you can read someone else's code, follow a project's contribution guidelines, and collaborate through code review. It's one of the most underrated additions to a junior developer's portfolio.

## A Game, Even a Simple One

Building a small game, like tic-tac-toe, a memory matching game, or a simple platformer, forces you to think about state management and user interaction in ways that a typical CRUD app doesn't. Games have clear win and lose conditions, require careful handling of user input, and often need some kind of animation or visual feedback, all of which are transferable skills even if you never build another game again.

## A Redesign of Something You Think Could Be Better

Pick a real website or app with a UI you think could be improved, and rebuild your version of it. This is a great way to practice both design thinking and front-end implementation without needing to invent an entirely new concept from scratch. Write a short explanation of what you changed and why, since the reasoning behind your decisions is often more impressive to a reviewer than the final pixels.

## Wrapping Up

The best portfolio project is the one you actually finish, so pick something from this list that genuinely interests you rather than whatever seems most impressive on paper. A smaller project you completed and can talk about in detail will always beat an ambitious one that's half-built and abandoned. Start small, ship something, and iterate from there.
