Authentication is one of those features that sounds simple until you build it. You need OAuth flows, token storage, session refresh, a user table, and a server to tie it all together. That's a lot of work for a button that says "Sign in with GitHub."

In this tutorial we'll skip most of it. Using **Supabase** as the backend and **React** on the front end, you'll have working GitHub authentication in about ten minutes, and you won't write a single line of server code.

## What We're Building

A small React app that:

- Shows a "Sign in with GitHub" button to logged-out users
- Redirects to GitHub, then back to your app
- Displays the user's name, avatar, and email once logged in
- Lets the user sign out

Supabase handles the OAuth handshake, stores users in a Postgres database, and manages sessions for you.

## Prerequisites

- Node.js 18 or newer
- A free [Supabase](https://supabase.com) account
- A GitHub account

## Step 1: Create a Supabase Project (2 minutes)

1. Log in to the Supabase dashboard and click **New project**.
2. Pick a name, set a database password, and choose a region.
3. Once the project is ready, go to **Project Settings → API** and copy two values:
   - **Project URL**
   - **anon / public key**

Keep these handy. We'll need them shortly.

## Step 2: Create a GitHub OAuth App (2 minutes)

GitHub needs to know which app is asking users to log in.

1. Go to **GitHub → Settings → Developer settings → OAuth Apps → New OAuth App**.
2. Fill in the form:
   - **Application name:** anything you like
   - **Homepage URL:** `http://localhost:5173`
   - **Authorization callback URL:** `https://<your-project-ref>.supabase.co/auth/v1/callback`

   You can find the exact callback URL in Supabase under **Authentication → Providers → GitHub**.
3. Click **Register application**, then **Generate a new client secret**.
4. Copy the **Client ID** and **Client Secret**.

Now head back to Supabase:

1. Open **Authentication → Providers → GitHub**.
2. Toggle it on, paste in the Client ID and Client Secret, and save.
3. Under **Authentication → URL Configuration**, set the **Site URL** to `http://localhost:5173`.

That's the entire "backend" setup.

## Step 3: Scaffold the React App (1 minute)

We'll use Vite for a fast setup:

```bash
npm create vite@latest supabase-github-auth -- --template react
cd supabase-github-auth
npm install
npm install @supabase/supabase-js
```

Create a `.env.local` file in the project root:

```bash
VITE_SUPABASE_URL=https://your-project-ref.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
```

The anon key is safe to expose in the browser. Supabase uses Row Level Security to protect your data, not secrecy of this key. Never put your `service_role` key in front-end code, though.

## Step 4: Initialize the Supabase Client (1 minute)

Create `src/supabaseClient.js`:

```javascript
import { createClient } from '@supabase/supabase-js'

export const supabase = createClient(
  import.meta.env.VITE_SUPABASE_URL,
  import.meta.env.VITE_SUPABASE_ANON_KEY
)
```

This single client handles auth, database queries, storage, and more.

## Step 5: Build the Auth UI (3 minutes)

Replace the contents of `src/App.jsx` with:

```jsx
import { useEffect, useState } from 'react'
import { supabase } from './supabaseClient'

export default function App() {
  const [session, setSession] = useState(null)
  const [loading, setLoading] = useState(true)

  useEffect(() => {
    // Check for an existing session on load
    supabase.auth.getSession().then(({ data: { session } }) => {
      setSession(session)
      setLoading(false)
    })

    // Listen for sign-in and sign-out events
    const { data: { subscription } } = supabase.auth.onAuthStateChange(
      (_event, session) => setSession(session)
    )

    return () => subscription.unsubscribe()
  }, [])

  const signInWithGitHub = async () => {
    const { error } = await supabase.auth.signInWithOAuth({
      provider: 'github',
      options: { redirectTo: window.location.origin },
    })
    if (error) console.error('Error signing in:', error.message)
  }

  const signOut = async () => {
    const { error } = await supabase.auth.signOut()
    if (error) console.error('Error signing out:', error.message)
  }

  if (loading) return <p>Loading...</p>

  if (!session) {
    return (
      <main style={{ textAlign: 'center', marginTop: '4rem' }}>
        <h1>Welcome 👋</h1>
        <button onClick={signInWithGitHub}>Sign in with GitHub</button>
      </main>
    )
  }

  const { user_metadata, email } = session.user

  return (
    <main style={{ textAlign: 'center', marginTop: '4rem' }}>
      <img
        src={user_metadata.avatar_url}
        alt="avatar"
        width={80}
        style={{ borderRadius: '50%' }}
      />
      <h2>Hello, {user_metadata.full_name || user_metadata.user_name}!</h2>
      <p>{email}</p>
      <button onClick={signOut}>Sign out</button>
    </main>
  )
}
```

Here's what's going on:

- **`getSession()`** checks whether the user is already logged in when the page loads. Supabase stores the session in local storage, so users stay signed in across refreshes.
- **`onAuthStateChange()`** fires whenever the user signs in, signs out, or their token refreshes. This keeps React state in sync automatically.
- **`signInWithOAuth()`** redirects the user to GitHub. After they approve, GitHub sends them to Supabase, which creates the session and redirects back to your app.
- **`user_metadata`** contains profile data from GitHub, including the avatar, username, and full name.

## Step 6: Run It (1 minute)

```bash
npm run dev
```

Open `http://localhost:5173`, click **Sign in with GitHub**, approve the app, and you'll land back on your page with your avatar and name displayed. 🎉

Check the Supabase dashboard under **Authentication → Users** and you'll see your account listed there. Supabase created it automatically in the `auth.users` table.

## Where to Go From Here

You now have real, production-grade authentication. A few natural next steps:

- **Protect your data:** Enable Row Level Security on your tables and write policies using `auth.uid()` so users can only access their own rows.
- **Create a profiles table:** Use a Postgres trigger to copy new users into a public `profiles` table for display names, bios, and so on.
- **Add more providers:** Google, Discord, and others work the same way. Enable them in the dashboard and change the `provider` value.
- **Deploy:** When you ship to Vercel or Netlify, add your production URL to the Site URL and Redirect URLs in Supabase, and update the homepage URL in your GitHub OAuth app.

## Wrapping Up

In about ten minutes, you set up a full-stack GitHub login: OAuth configuration, a hosted Postgres user store, persistent sessions, and a reactive React UI. You didn't need to run a server or touch a JWT library.

That's the real appeal of Supabase. It handles the plumbing so you can focus on building the parts of your app that matter.
