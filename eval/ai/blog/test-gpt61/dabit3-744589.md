# How to Build a Full Stack NFT Marketplace - V2 (2022)

An NFT marketplace brings together several familiar application features: user accounts, file uploads, product listings, and payments. The difference is where those responsibilities live.

A wallet represents the user. IPFS stores artwork and metadata. A smart contract records ownership and handles purchases. A React application connects everything.

In this tutorial, we’ll build a small marketplace where users can mint NFTs, list them for sale, and buy them with ETH.

This version uses a **2022-era stack**: Next.js 12, ethers.js 5, Hardhat 2, Solidity 0.8, and OpenZeppelin Contracts 4. The package versions are intentionally pinned so the examples use consistent APIs.

## 1. Understand the architecture

Our application has three main layers:

- **Frontend:** Next.js renders NFTs and requests wallet transactions.
- **Contract:** Solidity manages tokens, listings, and payments.
- **Storage:** IPFS holds images and JSON metadata.

The blockchain stores a token’s owner and metadata URI. It does not need to store the image itself.

We’ll combine the NFT collection and marketplace in one contract. Sellers retain their NFTs until a purchase completes, and the contract checks ownership before every sale.

This keeps the example compact. Supporting NFTs from arbitrary collections would require a separate marketplace contract and token approvals.

## 2. Create the project

Start with a Next.js application:

```bash

```

Create `hardhat.config.js`:

## 3. Write the marketplace contract

Create `contracts/Marketplace.sol`:

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.17;

import "@openzeppelin/contracts/token/ERC721/extensions/ERC721URIStorage.sol";
import "@openzeppelin/contracts/security/ReentrancyGuard.sol";

contract Marketplace is ERC721URIStorage, ReentrancyGuard {
    uint256 public tokenCount;

    struct Listing {
        address seller;
        uint256 price;
    }

    mapping(uint256 => Listing) public listings;
    mapping(address => uint256) public proceeds;

    event Listed(uint256 indexed tokenId, address seller, uint256 price);
    event Purchased(uint256 indexed tokenId, address buyer, uint256 price);

    constructor() ERC721("Marketplace NFT", "MNFT") {}

    function mint(string calldata uri) external returns (uint256) {
        uint256 tokenId = ++tokenCount;
        _mint(msg.sender, tokenId);
        _setTokenURI(tokenId, uri);
        return tokenId;
    }

    function list(uint256 tokenId, uint256 price) external {
        require(ownerOf(tokenId) == msg.sender, "Not owner");
        require(price > 0, "Invalid price");

        listings[tokenId] = Listing(msg.sender, price);
        emit Listed(tokenId, msg.sender, price);
    }

    function cancel(uint256 tokenId) external {
        require(listings[tokenId].seller == msg.sender, "Not seller");
        delete listings[tokenId];
    }

    function buy(uint256 tokenId) external payable nonReentrant {
        Listing memory item = listings[tokenId];

        require(item.price > 0, "Not listed");
        require(msg.value == item.price, "Incorrect payment");
        require(ownerOf(tokenId) == item.seller, "Owner changed");
        require(msg.sender != item.seller, "Already owner");

        delete listings[tokenId];
        proceeds[item.seller] += msg.value;

        _safeTransfer(item.seller, msg.sender, tokenId, "");
        emit Purchased(tokenId, msg.sender, msg.value);
    }

    function withdraw() external nonReentrant {
        uint256 amount = proceeds[msg.sender];
        require(amount > 0, "Nothing to withdraw");

        proceeds[msg.sender] = 0;

        (bool success, ) = payable(msg.sender).call{value: amount}("");
        require(success, "Withdrawal failed");
    }

    function _beforeTokenTransfer(
        address from,
        address to,
        uint256 tokenId
    ) internal override {
        super._beforeTokenTransfer(from, to, tokenId);
        delete listings[tokenId];
    }
}
```

`ERC721URIStorage` supplies token ownership, transfers, and per-token metadata URIs. These building blocks are documented in [OpenZeppelin’s ERC-721 reference](https://docs.openzeppelin.com/contracts/4.x/api/token/erc721).

Notice that purchases credit a seller’s balance instead of immediately sending ETH. Sellers withdraw their proceeds separately, so a seller’s payment receiver cannot block someone from buying.

We also clear listings whenever tokens move. Otherwise, a direct transfer could leave an old asking price attached to a new owner’s NFT.

## 4. Deploy locally

Create `scripts/deploy.js`:

```javascript
const hre = require("hardhat");

async function main() {
  const Factory = await hre.ethers.getContractFactory("Marketplace");
  const market = await Factory.deploy();

  await market.deployed();
  console.log("Marketplace:", market.address);
}

main().catch((error) => {
  console.error(error);
  process.exitCode = 1;
});
```

Start the blockchain in one terminal:

```bash
npx hardhat node
```

In another terminal, deploy:

```bash
npx hardhat run scripts/deploy.js --network localhost
```

Save the printed address in `.env.local`:

```text
NEXT_PUBLIC_MARKETPLACE_ADDRESS=YOUR_DEPLOYED_ADDRESS
```

Configure MetaMask with the RPC URL `http://127.0.0.1:8545` and chain ID `31337`. Import a development account printed by the local node.

Use those publicly known development keys only on your local network.

## 5. Prepare NFT metadata

Each token points to a JSON document:

```json
{
  "name": "First Light",
  "description": "An original digital illustration.",
  "image": "ipfs://YOUR_IMAGE_CID"
}
```

Upload your image through an IPFS pinning service, then upload this JSON with the image’s resulting URI.

The JSON receives its own CID. That metadata URI is what you pass to `mint()`.

For this first version, users paste an existing metadata URI into the app. To add an upload form later, send files through a server route that holds your pinning credentials. Keep those credentials out of browser code and `NEXT_PUBLIC_` environment variables.

Pin both files so they remain available.

## 6. Connect the frontend

Create `lib/marketplace.js`:

```javascript
import { ethers } from "ethers";
import artifact from "../artifacts/contracts/Marketplace.sol/Marketplace.json";

export async function getMarket() {
  if (!window.ethereum) {
    throw new Error("Install MetaMask to continue.");
  }

  const provider = new ethers.providers.Web3Provider(window.ethereum);
  await provider.send("eth_requestAccounts", []);

  const network = await provider.getNetwork();

  if (network.chainId !== 31337) {
    throw new Error("Switch to the local Hardhat network.");
  }

  return new ethers.Contract(
    process.env.NEXT_PUBLIC_MARKETPLACE_ADDRESS,
    artifact.abi,
    provider.getSigner()
  );
}
```

The provider communicates with Ethereum through the wallet. The signer authorizes transactions using the selected account.

The compiled artifact supplies the ABI: the description ethers needs to call our contract.

## 7. Build the marketplace page

Replace `pages/index.js` with a minimal interface:

```jsx
import { useState } from "react";
import { ethers } from "ethers";
import { getMarket } from "../lib/marketplace";

export default function Home() {
  const [uri, setUri] = useState("");
  const [tokenId, setTokenId] = useState("");
  const [price, setPrice] = useState("");
  const [items, setItems] = useState([]);
  const [status, setStatus] = useState("");
  const [busy, setBusy] = useState(false);

  async function refresh(market) {
    const count = (await market.tokenCount()).toNumber();
    const results = [];

    for (let id = 1; id <= count; id++) {
      const listing = await market.listings(id);

      if (!listing.price.isZero()) {
        results.push({
          id,
          uri: await market.tokenURI(id),
          price: listing.price.toString(),
        });
      }
    }

    setItems(results);
  }

  async function run(action) {
    setBusy(true);

    try {
      const market = await getMarket();
      await action(market);
      await refresh(market);
      setStatus("Ready.");
    } catch (error) {
      setStatus(error.reason || error.message);
    } finally {
      setBusy(false);
    }
  }

  async function confirm(transaction) {
    setStatus("Waiting for confirmation...");
    await (await transaction).wait();
  }

  return (
    <main>
      <h1>NFT Marketplace</h1>
      <p>{status}</p>

      <button disabled={busy} onClick={() => run(async () => {})}>
        Connect and refresh
      </button>

      <h2>Create</h2>
      <input
        placeholder="Metadata URI"
        value={uri}
        onChange={(event) => setUri(event.target.value)}
      />
      <button disabled={busy} onClick={() => run(
        (market) => confirm(market.mint(uri))
      )}>
        Mint
      </button>

      <h2>Manage a token</h2>
      <input
        placeholder="Token ID"
        value={tokenId}
        onChange={(event) => setTokenId(event.target.value)}
      />
      <input
        placeholder="Price in ETH"
        value={price}
        onChange={(event) => setPrice(event.target.value)}
      />
      <button disabled={busy} onClick={() => run(
        (market) => confirm(market.list(
          tokenId, ethers.utils.parseEther(price)
        ))
      )}>
        List
      </button>
      <button disabled={busy} onClick={() => run(
        (market) => confirm(market.cancel(tokenId))
      )}>
        Cancel listing
      </button>

      <h2>For sale</h2>
      {items.map((item) => (
        <article key={item.id}>
          <h3>Token #{item.id}</h3>
          <p>{item.uri}</p>
          <p>{ethers.utils.formatEther(item.price)} ETH</p>
          <button disabled={busy} onClick={() => run(
            (market) => confirm(market.buy(item.id, {
              value: item.price,
            }))
          )}>
            Buy
          </button>
        </article>
      ))}

      <button disabled={busy} onClick={() => run(
        (market) => confirm(market.withdraw())
      )}>
        Withdraw proceeds
      </button>
    </main>
  );
}
```

Run `npm run dev` and open the application.

Mint your first token, then list token ID `1`. Switch to another funded development account, refresh, and purchase it.

Prices stay as integer wei strings until display. Avoid JavaScript floating-point arithmetic for payment amounts.

## 8. Add artwork and verify the flow

The minimal page displays metadata URIs. For image cards, resolve `ipfs://` through an HTTP gateway, fetch the JSON, and render its `name`, `description`, and `image`.

Handle missing files and invalid JSON per card so one unavailable asset does not break the whole gallery.

Before extending the interface, test the contract’s boundaries:

- A non-owner cannot list a token.
- Incorrect payment reverts.
- Buying changes ownership and clears the listing.
- Direct transfers clear existing listings.
- Sellers can withdraw proceeds only once.

For a larger collection, replace the gallery’s sequential token scan with an indexer that processes contract events.

You now have the core marketplace flow: mint, list, buy, and withdraw. From here, useful additions include an owned-token dashboard, integrated uploads, searchable listings, and a more polished transaction experience.
