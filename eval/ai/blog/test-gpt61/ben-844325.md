# Using FastImage to detect image dimensions in Ruby

Suppose you’re building a link preview, importing product photos, or checking whether an uploaded banner is wide enough. You need an image’s width and height, but you don’t need to resize it or manipulate its pixels.

[FastImage](https://github.com/sdsykes/fastimage) handles that task with a small Ruby API. Give it an image URL, file path, or readable IO object, and it can return the dimensions.

For remote images, FastImage reads only as much data as it needs to identify the dimensions. This can avoid downloading a large image just to learn its size. It also works without an external image processing dependency such as ImageMagick. See the project’s [implementation notes](https://github.com/sdsykes/fastimage/blob/master/lib/fastimage.rb).

Let’s put it to work.

Add FastImage to your `Gemfile`:

```ruby
gem "fastimage"
```

Then install your dependencies:

```bash
bundle install
```

The main method is `FastImage.size`. It returns an array containing the width followed by the height:

```ruby
require "fastimage"

# Replace this with a URL you control.
url = "https://your-cdn.example/banner.png"
dimensions = FastImage.size(url)

if dimensions
  width, height = dimensions
  puts "#{width}px wide, #{height}px tall"
else
  puts "Could not determine image dimensions"
end
```

These are image dimensions, rather than the dimensions at which your browser happens to display the image. A responsive page might render the same image at several different sizes.

Checking the result before unpacking it also gives your application an explicit fallback when the image cannot be inspected.

The same API works with local files and open IO objects:

```ruby
dimensions = FastImage.size("public/images/banner.png")

File.open("public/images/banner.png", "rb") do |file|
  dimensions = FastImage.size(file)
  puts dimensions.inspect
end
```

Passing an IO object is useful when another part of your application already has a file open. URLs, local paths, and readable objects are all documented in the [FastImage README](https://github.com/sdsykes/fastimage#examples).

Once you have the dimensions, ordinary Ruby handles your application’s rules. For example, here’s a helper that checks whether a banner meets a minimum size:

```ruby
def banner_large_enough?(path)
  dimensions = FastImage.size(path)
  return false unless dimensions

  width, height = dimensions
  width >= 1200 && height >= 400
end
```

This helper deliberately treats unreadable images as unsuccessful checks. In an upload form, you might instead return separate messages for “image too small” and “could not read image,” so users know what to fix.

For remote requests, choose a timeout explicitly:

```ruby
dimensions = FastImage.size(url, timeout: 3)
```

The timeout applies to opening and reading the HTTP connection; treat it as a network setting rather than a guaranteed deadline for the entire operation.

FastImage normally returns `nil` for handled failures. When you need exceptions for logging or job retries, enable `raise_on_failure`:

```ruby
begin
  width, height = FastImage.size(
    url,
    timeout: 3,
    raise_on_failure: true
  )

  puts "#{width} × #{height}"
rescue FastImage::ImageFetchFailure
  warn "Could not fetch the image"
rescue FastImage::UnknownImageType, FastImage::SizeNotFound
  warn "Could not determine image dimensions"
end
```

The available options and exception classes are described in the [API source](https://github.com/sdsykes/fastimage/blob/master/lib/fastimage/fastimage.rb).

In a web application, consider detecting dimensions when an image is uploaded or imported, then storing them alongside its URL. That keeps repeated network requests out of page rendering. For larger imports, a background job gives you somewhere to handle retries and record failures.

Also keep the input boundary clear: FastImage accepts local paths as well as URLs. For a feature that accepts user-submitted URLs, use your application’s URL validation and outbound network controls before fetching them.

With dimensions stored, your views can reserve space for images, your upload forms can enforce size requirements, and your import jobs can flag unsuitable assets—all using the same straightforward Ruby API.
