# How to wrap a Preact component into a Stimulus controller

Server-rendered applications sometimes need a richer interface in one corner of a page. Maybe it’s an autocomplete field, a pricing calculator, or an editor with several interacting controls.

Stimulus gives that interface a lifecycle tied to the HTML document. Preact gives you components for describing what happens inside it. Wrapping a Preact component in a Stimulus controller lets you combine both approaches while keeping the integration small.

Let’s build a counter that receives its starting value from HTML, updates through Preact, and announces changes through Stimulus events. The counter is deliberately simple: the same boundary works for more involved widgets.

We’ll use plain JavaScript throughout, so this example doesn’t require JSX configuration.

First, install the dependencies:

```bash
npm install preact @hotwired/stimulus
```

The examples assume your application already bundles JavaScript and loads its entry point in the browser.

Start with a component that accepts a value and a callback:

```javascript
// components/counter.js
import { h } from "preact";

export default function Counter({ count, onChange }) {
  return h("div", { class: "counter" }, [
    h("p", { "aria-live": "polite" }, `Count: ${count}`),
    h(
      "button",
      {
        type: "button",
        onClick: () => onChange(count + 1),
      },
      "Increment"
    ),
  ]);
}
```

The component describes the interface and reports user intent through `onChange`. Its parent supplies the current count.

Using `h()` keeps the example executable without a JSX transform. If your project already supports Preact JSX, you can write the same component with familiar HTML-like syntax. Both approaches produce virtual DOM elements. See the [Preact API reference](https://preactjs.com/guide/v11/api-reference/).

Notice that the component doesn’t import Stimulus. Keeping that dependency outside the component makes it easier to reuse in another page, a preview, or a component test.

Next, give the widget a place in your HTML:

```html
<section
  data-controller="counter"
  data-counter-count-value="3"
>
  <h2>Try the counter</h2>
  <div data-counter-target="mount"></div>
</section>
```

The outer section belongs to Stimulus. The empty mount element provides a dedicated container for Preact.

This boundary is a useful design rule: let Preact manage the mount element’s descendants. Keep headings, surrounding forms, and other server-rendered content outside that subtree. Otherwise, two pieces of your application may try to update the same nodes.

Now create the wrapper:

```javascript
// controllers/counter_controller.js
import { Controller } from "@hotwired/stimulus";
import { h, render } from "preact";
import Counter from "../components/counter.js";

export default class extends Controller {
  static targets = ["mount"];
  static values = {
    count: { type: Number, default: 0 },
  };

  connect() {
    this.container = this.mountTarget;
    this.renderComponent();
  }

  disconnect() {
    if (this.container) {
      render(null, this.container);
      this.container = null;
    }
  }

  countValueChanged() {
    if (this.container) {
      this.renderComponent();
    }
  }

  renderComponent() {
    render(
      h(Counter, {
        count: this.countValue,
        onChange: (count) => {
          this.countValue = count;
          this.dispatch("change", { detail: { count } });
        },
      }),
      this.container
    );
  }
}
```

There are three responsibilities here: mounting the component, translating data into props, and unmounting it.

Stimulus calls `connect()` when the controller connects to the document and `disconnect()` when it disconnects. A controller instance can reconnect, so mounting belongs in `connect()` rather than the once-only `initialize()` callback. The [Stimulus lifecycle reference](https://stimulus.hotwired.dev/reference/lifecycle-callbacks) explains those guarantees.

Saving the container also gives cleanup a stable reference, even after the controller’s element leaves the document.

Calling `render(null, container)` unmounts the Preact tree. Avoid replacing this with `container.innerHTML = ""`: removing DOM nodes directly bypasses the component lifecycle. Components that acquire resources should release them in their effect cleanup functions, as described in the [Preact hooks documentation](https://preactjs.com/guide/v11/hooks/).

To activate the controller, register it in your application entry point:

```javascript
// application.js
import { Application } from "@hotwired/stimulus";
import CounterController from "./controllers/counter_controller.js";

const application = Application.start();
application.register("counter", CounterController);
```

If your application already starts Stimulus, register the controller with that existing application. Projects with automatic controller loading can use their established registration convention.

Load the page, and the counter should start at three. Clicking the button updates the controller’s value, which causes the component to receive new props.

The count lives in one place: the Stimulus value. That choice is intentional because this example treats the count as page-level state. The Preact component remains controlled by its props.

For a richer widget, temporary interface state—such as an expanded menu or a highlighted suggestion—can live inside Preact. Decide which layer owns each value before adding synchronization code.

Stimulus values connect typed JavaScript properties to HTML attributes. Here, `countValue` corresponds to `data-counter-count-value`. A change callback runs when that value changes, including its initial initialization. The container guard prevents that early callback from mounting before `connect()`. See the [Stimulus values reference](https://stimulus.hotwired.dev/reference/values).

You can therefore update the widget from outside Preact:

```javascript
const element = document.querySelector(
  '[data-controller="counter"]'
);

element.setAttribute("data-counter-count-value", "10");
```

Stimulus observes the change and invokes the callback asynchronously. The wrapper then renders the component with the new count.

Rendering again into the same container lets Preact update its existing tree. Keep the component type and its position stable when you want to preserve component-local state.

Communication in the other direction uses the callback passed to `Counter`. The wrapper updates its value and dispatches an event:

```javascript
document.addEventListener("counter:change", (event) => {
  console.log("New count:", event.detail.count);
});
```

By default, Stimulus prefixes dispatched event names with the controller identifier and makes them bubble. That lets surrounding code subscribe without reaching into the component. The behavior is documented under [cross-controller coordination](https://stimulus.hotwired.dev/reference/controllers#cross-controller-coordination-with-events).

Here, the event represents a user interaction. An external attribute update refreshes the component without emitting another change event, which helps keep synchronization loops out of the integration.

Before shipping, check three behaviors: the initial value appears, an external attribute update reaches the component, and removing then reinserting the controller element mounts it again cleanly. For components with subscriptions or timers, verify their cleanup too.

The wrapper can stay this small as the interface grows. Stimulus handles the connection to the page; Preact handles the component tree; props and callbacks define the boundary between them.
