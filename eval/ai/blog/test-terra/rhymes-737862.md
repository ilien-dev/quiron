# How to wrap a Preact component into a Stimulus controller

Stimulus is a great fit for adding behavior to server-rendered HTML. But sometimes a small part of a page needs richer state and rendering than you want to manage with DOM manipulation alone.

That’s where Preact can help. Instead of turning the whole page into a single-page application, you can mount a Preact component inside a Stimulus controller and let each library do what it does best.

In this post, we’ll build a small counter component, wrap it in a Stimulus controller, pass data from HTML into Preact, and send events back to the page. We’ll also handle cleanup so the component works well with navigation tools such as Turbo.

## What we’re building

Our example will have three layers:

1. **HTML** provides the initial count and a place to mount the component.
2. **Stimulus** manages the component’s lifecycle and bridges it to the rest of the page.
3. **Preact** renders the counter and handles its interactive state.

The result is a self-contained interactive island you can place wherever your server renders HTML.

## Install the dependencies

If your project already uses Stimulus, you only need to add Preact. Otherwise, install both packages:

```bash
npm install preact @hotwired/stimulus
```

The examples use ES modules and JSX, so you’ll also need a build tool configured to compile JSX for Preact. For example, with Vite, install its Preact plugin:

```bash
npm install -D vite @preact/preset-vite
```

Then add it to your Vite configuration:

```js
// vite.config.js
import { defineConfig } from "vite"
import preact from "@preact/preset-vite"

export default defineConfig({
  plugins: [preact()],
})
```

If your application already has a build setup, use its Preact-compatible JSX configuration instead.

## Create the Preact component

Let’s start with a counter. It receives its current count as a prop and calls `onChange` when the user clicks a button.

```jsx
// components/Counter.jsx
export function Counter({ count, onChange }) {
  return (
    <div>
      <p aria-live="polite">Count: {count}</p>

      <button type="button" onClick={() => onChange(count - 1)}>
        Decrease
      </button>

      <button type="button" onClick={() => onChange(count + 1)}>
        Increase
      </button>
    </div>
  )
}
```

This component doesn’t know anything about Stimulus. It receives data and reports changes through props, which makes it easy to reuse in another Preact application.

The count will live in the Stimulus controller. That gives the surrounding page a way to read or update it through a data attribute.

## Add the HTML

Next, add a controller element with a Stimulus value and an empty mount point:

```html
<div
  data-controller="counter"
  data-counter-count-value="5"
>
  <div data-counter-target="mount"></div>
</div>
```

The controller’s identifier is `counter`, so Stimulus maps `data-counter-count-value` to `countValue` in JavaScript. The inner `div` is where Preact will render.

Keeping a dedicated mount point makes ownership clear: Stimulus manages the outer element, while Preact manages the contents of the inner element. Avoid putting server-rendered content inside that mount point unless you’ve deliberately designed how it should be handled.

## Wrap the component in a controller

Create the Stimulus controller:

```jsx
// controllers/counter_controller.jsx
import { Controller } from "@hotwired/stimulus"
import { h, render } from "preact"
import { Counter } from "../components/Counter"

export default class extends Controller {
  static targets = ["mount"]

  static values = {
    count: { type: Number, default: 0 },
  }

  connect() {
    this.connected = true
    this.renderCounter()
  }

  disconnect() {
    this.connected = false
    render(null, this.mountTarget)
  }

  countValueChanged() {
    if (this.connected) {
      this.renderCounter()
    }
  }

  renderCounter() {
    render(
      h(Counter, {
        count: this.countValue,
        onChange: (count) => this.updateCount(count),
      }),
      this.mountTarget
    )
  }

  updateCount(count) {
    this.countValue = count

    this.dispatch("changed", {
      detail: { count },
    })
  }
}
```

We use Preact’s `h()` function in the controller, so the controller itself doesn’t need JSX. The component still does.

Here’s what happens:

- When Stimulus connects the controller, `connect()` renders the component.
- Clicking a button calls `updateCount()`, which updates the Stimulus value.
- Stimulus calls `countValueChanged()`, and the controller renders the component with the new count.
- When the controller disconnects, `render(null, ...)` unmounts the Preact component.

Stimulus invokes value change callbacks during initialization as well as when an attribute changes. The `connected` guard ensures the initial callback doesn’t render before `connect()`; the first render happens in `connect()` itself. See the [Stimulus values reference](https://stimulus.hotwired.dev/reference/values) for details.

Notice that setting `this.countValue` also updates `data-counter-count-value` on the controller element. The HTML attribute becomes the shared source of truth for this example.

## Register the controller

If your application already registers Stimulus controllers automatically, add the new controller according to your project’s conventions.

For a minimal manual setup, register it in your JavaScript entry point:

```js
// main.js
import { Application } from "@hotwired/stimulus"
import CounterController from "./controllers/counter_controller"

const application = Application.start()
application.register("counter", CounterController)
```

Make sure your page loads the compiled entry point as a module. Once it does, the counter should start at `5` and respond to both buttons.

You can add another instance with a different starting value:

```html
<div data-controller="counter" data-counter-count-value="12">
  <div data-counter-target="mount"></div>
</div>
```

Each controller instance manages its own value and Preact mount point.

## Listen for changes outside Preact

The `dispatch()` call in `updateCount()` emits a `counter:changed` event. Another Stimulus controller can listen to it using an action:

```html
<div
  data-controller="summary"
  data-action="counter:changed->summary#showCount"
>
  <div data-controller="counter" data-counter-count-value="5">
    <div data-counter-target="mount"></div>
  </div>

  <p data-summary-target="output"></p>
</div>
```

Here’s the receiving controller:

```js
// controllers/summary_controller.js
import { Controller } from "@hotwired/stimulus"

export default class extends Controller {
  static targets = ["output"]

  showCount(event) {
    this.outputTarget.textContent =
      `The counter changed to ${event.detail.count}.`
  }
}
```

Register this controller as `summary` in the same way as the counter. Because the event bubbles, the parent can receive it without the Preact component knowing anything about the summary.

## Why cleanup matters

A Stimulus controller can disconnect when its element is removed, including during a Turbo page change. It can also reconnect later. Stimulus documents these behaviors in its [lifecycle callbacks reference](https://stimulus.hotwired.dev/reference/lifecycle-callbacks).

Unmounting Preact in `disconnect()` lets it run component cleanup, including cleanup functions from effects. On reconnection, `connect()` renders the component again using the current Stimulus value.

If you introduce timers, subscriptions, or event listeners inside the Preact component, clean them up in the component too. The controller handles the boundary; the component remains responsible for the resources it creates.

## Where to go next

This pattern works for date pickers, autocomplete fields, charts, and other interactive pieces that benefit from component-based rendering. Start with a clear boundary: pass data in through props, report changes through callbacks or events, and let Stimulus mount and unmount the component.

You can keep the rest of your application server-rendered while giving individual parts of the page the interactivity they need.
