# How to Build a Full Stack NFT Marketplace - V2 (2022)

An NFT marketplace brings together several pieces of a Web3 application: a smart contract that manages ownership and sales, storage for artwork and metadata, and a frontend that lets people interact with both.

In this tutorial, we’ll build a small marketplace where users can mint an NFT, list it for a fixed price, and buy an NFT listed by someone else. We’ll use Solidity, Hardhat, OpenZeppelin, ethers.js, and React.

This is a learning project with a **2022-style stack**: Hardhat 2, ethers 5, and OpenZeppelin Contracts 4. Production marketplaces need additional security review, indexing, and operational work, which we’ll discuss at the end.

## How the marketplace works

Our application has three main layers:

1. **Smart contract:** Mints ERC-721 tokens, holds listed NFTs in escrow, and manages sales.
2. **Metadata storage:** Stores each NFT’s name, description, and image URI.
3. **Frontend:** Connects a wallet and sends transactions to the contract.

When someone lists an NFT, the contract transfers it into escrow. When a buyer pays the asking price, the contract transfers the NFT to the buyer and credits the seller’s balance. The seller can then withdraw their proceeds.

We’ll use a separate withdrawal step so a seller’s inability to receive ETH does not block a sale.

## Prerequisites

You’ll need:

- Node.js and npm
- A browser wallet such as MetaMask
- Basic familiarity with JavaScript and React
- Some familiarity with Ethereum transactions

We’ll run everything on a local Hardhat network first. Local test accounts and their private keys are public development credentials; never use them to hold real funds.

## 1. Set up the project

Create a directory and install the contract dependencies:

```bash
mkdir nft-marketplace-v2
cd nft-marketplace-v2

npm init -y
npm install --save-dev hardhat@2.12.7 \
  @nomiclabs/hardhat-ethers@2.2.3 ethers@5.7.2

```

Create `hardhat.config.js`:

```js
require("@nomiclabs/hardhat-ethers");

module.exports = {

```

Next, create a `contracts` directory. We’ll put the NFT and marketplace logic in one contract to keep the example focused.

## 2. Write the marketplace contract

Create `contracts/Marketplace.sol`:

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.17;

import "@openzeppelin/contracts/token/ERC721/extensions/ERC721URIStorage.sol";
import "@openzeppelin/contracts/security/ReentrancyGuard.sol";

contract Marketplace is ERC721URIStorage, ReentrancyGuard {
    uint256 private nextTokenId;

    struct Listing {
        address seller;
        uint256 price;
    }

    mapping(uint256 => Listing) public listings;
    mapping(address => uint256) public proceeds;

    event Listed(
        uint256 indexed tokenId,
        address indexed seller,
        uint256 price
    );
    event Sale(
        uint256 indexed tokenId,
        address indexed seller,
        address indexed buyer,
        uint256 price
    );
    event Canceled(uint256 indexed tokenId);
    event Withdrawal(address indexed seller, uint256 amount);

    constructor() ERC721("Marketplace NFT", "MNFT") {}

    function mint(string calldata uri) external returns (uint256) {
        uint256 tokenId = nextTokenId++;
        _safeMint(msg.sender, tokenId);
        _setTokenURI(tokenId, uri);
        return tokenId;
    }

    function list(uint256 tokenId, uint256 price) external {
        require(ownerOf(tokenId) == msg.sender, "Not token owner");
        require(price > 0, "Price must be positive");

        listings[tokenId] = Listing(msg.sender, price);
        _transfer(msg.sender, address(this), tokenId);

        emit Listed(tokenId, msg.sender, price);
    }

    function buy(uint256 tokenId) external payable nonReentrant {
        Listing memory listing = listings[tokenId];

        require(listing.seller != address(0), "Not listed");
        require(msg.sender != listing.seller, "Seller cannot buy");
        require(msg.value == listing.price, "Incorrect payment");

        delete listings[tokenId];
        proceeds[listing.seller] += msg.value;

        _safeTransfer(address(this), msg.sender, tokenId, "");

        emit Sale(tokenId, listing.seller, msg.sender, msg.value);
    }

    function cancel(uint256 tokenId) external nonReentrant {
        Listing memory listing = listings[tokenId];
        require(listing.seller == msg.sender, "Not seller");

        delete listings[tokenId];
        _safeTransfer(address(this), msg.sender, tokenId, "");

        emit Canceled(tokenId);
    }

    function withdraw() external nonReentrant {
        uint256 amount = proceeds[msg.sender];
        require(amount > 0, "No proceeds");

        proceeds[msg.sender] = 0;
        (bool sent, ) = payable(msg.sender).call{value: amount}("");
        require(sent, "Withdrawal failed");

        emit Withdrawal(msg.sender, amount);
    }
}
```

Let’s unpack the important parts:

- `mint` creates an NFT and associates it with a metadata URI.
- `list` transfers an owner’s NFT into the marketplace contract.
- `buy` checks the payment, credits the seller, and transfers the NFT.
- `cancel` lets the seller recover an unsold NFT.
- `withdraw` lets the seller claim their sale proceeds.

The contract updates its state before making external calls, and `ReentrancyGuard` adds protection around the functions that make those calls. OpenZeppelin’s [ERC-721 documentation](https://docs.openzeppelin.com/contracts/4.x/erc721) explains how the underlying token and URI storage work.

Compile the contract:

```bash
npx hardhat compile
```

## 3. Store NFT metadata

An NFT usually stores a URI pointing to metadata rather than the image itself. A simple metadata file might look like this:

```json
{
  "name": "Sunset #1",
  "description": "A sunset from my first NFT collection.",
  "image": "ipfs://IMAGE_CID"
}
```

Upload your image to an IPFS pinning provider, replace `IMAGE_CID`, and then upload the JSON file. The URI you pass to `mint` will look like:

```text
ipfs://METADATA_CID
```

IPFS content addressing helps identify the content, but availability still depends on someone retaining and serving it. Use a pinning provider and keep backups. Marketplaces commonly read this JSON through the token’s `tokenURI`; see [OpenSea’s metadata standard](https://docs.opensea.io/docs/metadata-standards).

For this tutorial, upload the image and JSON manually. An upload form can be added later, ideally with provider credentials protected by a backend.

## 4. Deploy to a local network

Create `scripts/deploy.js`:

```js
const { ethers } = require("hardhat");

async function main() {
  const Marketplace = await ethers.getContractFactory("Marketplace");
  const marketplace = await Marketplace.deploy();

  await marketplace.deployed();

  console.log("Marketplace deployed to:", marketplace.address);
}

main().catch((error) => {
  console.error(error);
  process.exitCode = 1;
});
```

Start a local blockchain in one terminal:

```bash
npx hardhat node
```

In a second terminal, deploy the contract:

```bash
npx hardhat run scripts/deploy.js --network localhost
```

Copy the deployed address. You’ll use it in the frontend.

To interact through a browser wallet, add the local RPC network at `http://127.0.0.1:8545`, using the chain ID printed by Hardhat, normally `31337`. Import one of the local accounts printed by Hardhat into your wallet. Use a second local account when testing purchases.

## 5. Create the React frontend

From the project root, create a React app and install ethers 5:

```bash
npx create-react-app client
cd client
npm install ethers@5.7.2
```

After compilation, copy the generated artifact into the React app:

```text
artifacts/contracts/Marketplace.sol/Marketplace.json
    → client/src/Marketplace.json
```

Replace `client/src/App.js` with the following. Insert your deployed contract address where indicated.

```jsx
import { useState } from "react";
import { ethers } from "ethers";
import artifact from "./Marketplace.json";

const ADDRESS = "PASTE_DEPLOYED_CONTRACT_ADDRESS";

export default function App() {
  const [uri, setUri] = useState("");
  const [tokenId, setTokenId] = useState("");
  const [price, setPrice] = useState("");
  const [status, setStatus] = useState("");

  async function run(action) {
    try {
      if (!window.ethereum) throw new Error("Install a browser wallet");

      await window.ethereum.request({ method: "eth_requestAccounts" });
      const provider = new ethers.providers.Web3Provider(window.ethereum);

      const { chainId } = await provider.getNetwork();
      if (chainId !== 31337) {
        throw new Error("Switch your wallet to the local Hardhat network");
      }

      const contract = new ethers.Contract(
        ADDRESS,
        artifact.abi,
        provider.getSigner()
      );

      setStatus("Confirm the transaction in your wallet...");
      const tx = await action(contract);
      setStatus(`Transaction submitted: ${tx.hash}`);
      await tx.wait();
      setStatus("Transaction confirmed!");
    } catch (error) {
      setStatus(error.reason || error.message);
    }
  }

  return (
    <main>
      <h1>NFT Marketplace</h1>

      <section>
        <h2>Mint an NFT</h2>
        <input
          placeholder="Metadata URI"
          value={uri}
          onChange={(event) => setUri(event.target.value)}
        />
        <button onClick={() => run((contract) => contract.mint(uri))}>
          Mint
        </button>
      </section>

      <section>
        <h2>Manage a listing</h2>
        <input
          placeholder="Token ID"
          value={tokenId}
          onChange={(event) => setTokenId(event.target.value)}
        />
        <input
          placeholder="Price in ETH"
          value={price}
          onChange={(event) => setPrice(event.target.value)}
        />
        <button
          onClick={() =>
            run((contract) =>
              contract.list(tokenId, ethers.utils.parseEther(price))
            )
          }
        >
          List
        </button>
        <button
          onClick={() =>
            run(async (contract) => {
              const listing = await contract.listings(tokenId);
              return contract.buy(tokenId, { value: listing.price });
            })
          }
        >
          Buy
        </button>
        <button onClick={() => run((contract) => contract.cancel(tokenId))}>
          Cancel listing
        </button>
      </section>

      <section>
        <h2>Seller proceeds</h2>
        <button onClick={() => run((contract) => contract.withdraw())}>
          Withdraw
        </button>
      </section>

      <p role="status">{status}</p>
    </main>
  );
}
```

Start the frontend:

```bash
npm start
```

The purchase button reads the current listing price before submitting the transaction. If the listing changes before the transaction is mined, the contract’s checks cause the transaction to revert rather than accept an incorrect payment.

This interface uses a manually entered token ID to keep the example compact. The first minted token has ID `0`; the next has ID `1`, and so on.

## 6. Try a complete sale

With the local node, contract, and React app running:

1. Connect the first local account and mint an NFT using your metadata URI.
2. Enter its token ID and a price such as `0.1`, then click **List**.
3. Switch to a second funded local account and click **Buy**.
4. Switch back to the seller account and click **Withdraw**.

You can also list another token and cancel it. Check the wallet and transaction output to see how ownership and balances change. Restarting the local node resets its blockchain state, so you’ll need to deploy again and update the frontend address.

## 7. What comes next?

The example demonstrates a complete transaction flow, but there’s plenty of room to grow:

- **Display listings:** Read `Listed`, `Sale`, and `Canceled` events into an index, then render active items with their metadata.
- **Improve the UI:** Show account, network, token details, balances, transaction errors, and loading states.
- **Test the contract:** Cover successful sales, cancellations, incorrect payments, unauthorized actions, withdrawal failures, and reentrancy attempts.
- **Support other collections:** This contract only lists NFTs minted by itself. Supporting external ERC-721 collections requires handling approvals and collection addresses.
- **Add production safeguards:** Review metadata handling, RPC reliability, indexing, fees, royalties, and contract security. Get an independent audit before handling valuable assets.

You now have the core of a full stack marketplace: an ERC-721 contract, metadata storage, wallet-connected transactions, and a React interface. From here, the most useful next step is to build a listing gallery so users can discover NFTs without knowing their token IDs.
