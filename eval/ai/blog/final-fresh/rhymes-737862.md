# How to wrap a Preact component into a Stimulus controller

I had to wrap a Preact component inside a Stimulus controller, load Preact and the component lazily (only when the controller connects) and talk to it with custom events. This is how I did it. I'm assuming you already know Preact and Stimulus, so I won't explain the basics of either.

This builds on the work Suzanne Aitchison (@s_aitchison) did last February: [forem/forem#12511](https://github.com/forem/forem/pull/12511), which added a Stimulus [modal controller](https://github.com/forem/forem/blob/main/app/javascript/admin/controllers/modal_controller.js) to the Admin. Go read it, it's where the idea comes from.

Some context: on Forem the public site uses Preact and vanilla JS, while some of the Admin views use Stimulus. Yesterday I was working on interactions in the Admin and I wanted to reuse Forem's [Snackbar](https://storybook.dev.to/?path=/story/app-components-snackbar-snackbar--simulate-adding-snackbar-items), which looks a lot like the [Material snackbar](https://material.io/components/snackbars). But the Snackbar is a Preact component and the Admin speaks Stimulus.

I haven't looked at the Snackbar internals. All I know is that the module exports `Snackbar` and `addSnackbarItem`, and that turned out to be enough.

## The container is a target

The Snackbar needs an element to render into. In Stimulus that's what [targets](https://stimulus.hotwire.dev/reference/targets) are for, so the container becomes `snackZoneTarget`. I kept the "snackZone" name Forem already uses, so anyone coming from the Preact side of the codebase will recognize it.

## Mount on connect, unmount on disconnect

Stimulus has [lifecycle callbacks](https://stimulus.hotwire.dev/reference/lifecycle-callbacks) that fit this job really well: `connect()` and `disconnect()`. When the controller connects I import Preact's [render](https://preactjs.com/guide/v10/api-reference#render) and the Snackbar asynchronously, then render the component into the target. When it disconnects I unmount it.

```js
// snackbar_controller.js
import { Controller } from "@hotwired/stimulus"

export default class extends Controller {
  static targets = ["snackZone"]

  async connect() {
    const [{ h, render }, { Snackbar }] = await Promise.all([
      import("preact"),
      import("./Snackbar"), // wherever the Snackbar module lives
    ])

    render(h(Snackbar), this.snackZoneTarget)
  }

  async disconnect() {
    const { render } = await import("preact")
    render(null, this.snackZoneTarget)
  }

  async addItem(event) {
    const { message, dismissible } = event.detail
    const { addSnackbarItem } = await import("./Snackbar")

    addSnackbarItem({ message, dismissible })
  }
}
```

Because of the dynamic imports, pages that never use the controller never download Preact or the Snackbar. Rendering `null` on disconnect lets Preact unmount the component, so nothing is left behind when the element goes away.

## Talking to it with custom events

This is the part I like the most. I didn't want the code that shows a message to know anything about Stimulus or Preact, so the two sides talk through a [CustomEvent](https://developer.mozilla.org/en-US/docs/Web/API/CustomEvent/CustomEvent). If you haven't used custom events with data attached, MDN has a good section on [adding custom data](https://developer.mozilla.org/en-US/docs/Web/Events/Creating_and_triggering_events#adding_custom_data_%E2%80%93_customevent).

The `body` gets the controller and an action that listens on the document:

```html
<body
  data-controller="snackbar"
  data-action="snackbar:add@document->snackbar#addItem"
>
  <div data-snackbar-target="snackZone"></div>
  ...
</body>
```

Every time a `snackbar:add` event reaches the document, Stimulus calls `addItem`, which pulls the message and the dismissible flag out of the payload, imports `addSnackbarItem` and calls it.

The publisher is plain [EventTarget.dispatchEvent](https://developer.mozilla.org/en-US/docs/Web/API/EventTarget/dispatchEvent):

```js
document.dispatchEvent(
  new CustomEvent("snackbar:add", {
    detail: { message: "Saved!", dismissible: true },
  })
)
```

That line can live in any JavaScript on the page. It doesn't need to be inside a Stimulus controller, and it doesn't need to know the Snackbar is a Preact component. That's the whole point of the decoupling: the publisher fires an event and whoever is listening takes care of it.

## Where this could go

You could push the same idea further and build a global event bus, something like the [Events API Vue removed in version 3](https://v3.vuejs.org/guide/migration/events-api.html#events-api). I'm not going to do that here, it's out of scope, but it would work with the same pieces: custom events on the document and controllers that listen for them.

What do you think? Would you wire it the same way?
