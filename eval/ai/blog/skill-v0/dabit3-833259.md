# 10 minute tutorial: full stack GitHub authentication with Supabase and React

Authentication is one of those things every app needs, and it's also one of those things nobody really wants to build from scratch. In this tutorial we'll add GitHub login to a React app using Supabase, and we'll do it in about 10 minutes.

By the end you'll have:

- A React app where users can sign in with GitHub
- A session that persists across page reloads
- A protected view that only signed-in users can see
- A sign out button

## Step 1: Create a Supabase project

Head over to [supabase.com](https://supabase.com) to sign in and create a new project. Give it a name and a database password, pick a region, and wait a minute or two for it to spin up.

When it's ready go to **Project Settings → API** and grab two values, the **Project URL** and the **anon public key**. We'll use both in the React app shortly.

## Step 2: Create a GitHub OAuth app

Next we need to register our application with GitHub.

1. Go to GitHub **Settings → Developer settings → OAuth Apps → New OAuth App**.
2. Fill in the registration form. The application name can be anything you like, and the homepage URL is `http://localhost:5173`. The authorization callback URL comes from Supabase: in your Supabase dashboard, go to **Authentication → Providers → GitHub** and copy the callback URL shown there. It looks like `https://<your-project>.supabase.co/auth/v1/callback`.
3. Then click the **Register application** button to save it.
4. Copy the **Client ID**, then generate and copy a **Client Secret**.

Now go back to Supabase and under **Authentication → Providers → GitHub**, enable the provider, paste in the Client ID and Client Secret, and save.

Finally, under **Authentication → URL Configuration**, make sure `http://localhost:5173` is set as the Site URL (or added to the redirect URLs). That's all the configuration we need, so now we can write the code.

## Step 3: Create the React app

I'm using Vite for this:

```bash
npm create vite@latest supabase-github-auth -- --template react
cd supabase-github-auth
npm install
npm install @supabase/supabase-js
```

Create a `.env` file in the root of the project:

```bash
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
```

## Step 4: Create the Supabase client

Create a new file at `src/supabaseClient.js`:

```javascript
import { createClient } from '@supabase/supabase-js';

export const supabase = createClient(
  import.meta.env.VITE_SUPABASE_URL,
  import.meta.env.VITE_SUPABASE_ANON_KEY
);
```

The anon key is safe to use in the browser. Supabase uses Row Level Security on the database side to control what each user can actually access.

## Step 5: Build the app

Now open `src/App.jsx` and replace its contents with this:

```jsx
import { useEffect, useState } from 'react';
import { supabase } from './supabaseClient';

function App() {
  const [session, setSession] = useState(null);

  useEffect(() => {
    // Get the current session on load
    supabase.auth.getSession().then(({ data: { session } }) => {
      setSession(session);
    });

    // Listen for sign in / sign out
    const {
      data: { subscription },
    } = supabase.auth.onAuthStateChange((_event, session) => {
      setSession(session);
    });

    return () => subscription.unsubscribe();
  }, []);

  async function signInWithGitHub() {
    const { error } = await supabase.auth.signInWithOAuth({
      provider: 'github',
    });
    if (error) console.error(error.message);
  }

  async function signOut() {
    await supabase.auth.signOut();
  }

  if (!session) {
    return (
      <div style={{ padding: 40 }}>
        <h1>Welcome</h1>
        <button onClick={signInWithGitHub}>Sign in with GitHub</button>
      </div>
    );
  }

  const { user } = session;

  return (
    <div style={{ padding: 40 }}>
      <h1>Hello, {user.user_metadata.user_name}!</h1>
      <img
        src={user.user_metadata.avatar_url}
        alt="avatar"
        width={80}
        style={{ borderRadius: '50%' }}
      />
      <p>Signed in as {user.email}</p>
      <button onClick={signOut}>Sign out</button>
    </div>
  );
}

export default App;
```

When the app loads, `getSession()` checks whether there's already a signed-in user. Supabase stores the session in local storage, so users stay logged in after a refresh.

`onAuthStateChange()` subscribes to auth events. When the user comes back from GitHub, Supabase picks up the tokens from the URL, creates the session and fires this listener, and all we do in the listener is update our state.

`signInWithOAuth({ provider: 'github' })` redirects the user to GitHub to authorize the app. After they approve it, GitHub sends them back to Supabase, and Supabase sends them back to your app.

`signOut()` clears the session. That also triggers the listener, so the UI flips back to the sign-in screen.

## Step 6: Run it

```bash
npm run dev
```

Open `http://localhost:5173`, click **Sign in with GitHub** and approve the app. You should land back on your page with your GitHub username and avatar showing, and if you refresh the page you'll still be signed in.

You can also check the **Authentication → Users** section of your Supabase dashboard, where your new user will be listed.

## Bonus: using the user in your database

The "full stack" part gets interesting once you start storing data. Say you have a `notes` table with a `user_id` column. You can enable Row Level Security and add a policy like this in the SQL editor:

```sql
alter table notes enable row level security;

create policy "Users can manage their own notes"
on notes
for all
using (auth.uid() = user_id)
with check (auth.uid() = user_id);
```

Now a query like this from your React app will only ever return the signed-in user's notes:

```javascript
const { data } = await supabase.from('notes').select('*');
```

You don't write any backend code or a custom API for this, because the database itself enforces who can see what.

## Recap

In about 10 minutes we created a Supabase project, registered a GitHub OAuth app, wired up sign in, sign out and session persistence in React, and saw how Row Level Security ties users to their data.

From here you could add additional providers like Google or Discord (it's exactly the same flow with a different `provider` value), add routing with protected pages, or start building out your data model.
