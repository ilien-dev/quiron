# State of the API, October/November 2019

One of DEV's goals is to be open and collaborative. The code is [open source](https://github.com/thepracticaldev/dev.to), and there's also [an API](https://dev.to/api/) you can use to build things on top of DEV. This post is a snapshot of the API as it is right now, warts included.

## How to access it

Public endpoints don't need any authentication, so you can just open [https://dev.to/api/articles](https://dev.to/api/articles) in your browser and see what comes back.

For everything else there are three ways to authenticate:

- **API keys**, which work with both public and private endpoints. You can generate one from your [account settings](https://dev.to/settings/account)
- **OAuth2**, which is in private testing and only works with some endpoints. This is the one meant for third-party apps
- **HTTP session**, for the endpoints that are only used by our own frontend

A bit of history explains why it looks like this: we built the API for internal use before DEV was open source, then opened it up gradually and only added API keys later.

## Stability

The API is v0 and it's in beta, but what we promise is that there won't be breaking changes: if something is quirky today, it will stay quirky until the next version. We don't have a formal deprecation policy yet.

## What's in it

These are the resources you can work with right now:

- articles
- comments
- chat channels
- videos
- podcasts
- tags
- listings
- analytics (in private testing)
- users

Keep in mind that we cache responses at the edge, so you may get stale data from time to time, and we cache some of the heavier endpoints on the server side too.

## What needs work

Quite a lot, honestly: bugs, resources and fields that are missing, the documentation and the caching.

The most notable bug is [#2250](https://github.com/thepracticaldev/dev.to/issues/2250). There are also a few feature requests open in [the issue tracker](https://github.com/thepracticaldev/dev.to/issues/):

- [#3654](https://github.com/thepracticaldev/dev.to/issues/3654): tag filtering
- [#3669](https://github.com/thepracticaldev/dev.to/issues/3669): CRUD for series
- [#4195](https://github.com/thepracticaldev/dev.to/issues/4195): CORS for the public endpoints
- [#4419](https://github.com/thepracticaldev/dev.to/issues/4419): video upload

## Documentation

The docs live at [docs.dev.to/api](https://docs.dev.to/api/), written in YAML as an OpenAPI 3.0 spec, and we autogenerate the HTML version at each deploy.

The problem is that most endpoints aren't in there yet, and if you want to help, the meta issue for that is [#4474](https://github.com/thepracticaldev/dev.to/issues/4474).

When the API changes we announce it in the [changelog tag](https://dev.to/t/changelog), so follow that if you build on top of it.
