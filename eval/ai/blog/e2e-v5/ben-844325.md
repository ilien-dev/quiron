# Using FastImage to Detect Image Dimensions in Ruby

In Forem (the open source software behind DEV), admins can configure display units that include images. The trouble with images that come without a height and width is that the browser doesn't know how much space to reserve for them, so the content jumps around as they load. That's frustrating for readers, and Google penalizes it as cumulative layout shift. I wrote about CLS in more detail [here](https://dev.to/ben/fixing-cumulative-layout-shift-41ja).

The easy answer would be to have admins type in the dimensions. But these images are user-generated, and asking people to enter sizes by hand is error-prone and a waste of their time. We should be able to figure that out ourselves.

## Enter FastImage

[FastImage](https://github.com/sdsykes/fastimage) is a Ruby gem that does exactly this. It reads as few bytes of the file as it needs to find the dimensions, and never downloads the whole image or opens it with an image-processing library. Common formats keep that information near the start of the file, so it usually doesn't have to go far.

Add it to your `Gemfile`:

```ruby
gem "fastimage"
```

Then pass it a URL and you get back the width and height:

```ruby
url = "https://example.com/images/header.jpg"

width, height = FastImage.size(url)

puts "Width: #{width}px"
puts "Height: #{height}px"
```

It can tell you the format too, if you need that:

```ruby
type = FastImage.type(url)

puts type
# => :jpeg
```

Remote images are unreliable (the URL might be down, slow, or not an image at all), and `FastImage.size` returns `nil` when it can't work the dimensions out. If you'd rather get an exception, and you probably want a timeout either way, there are options for both:

```ruby
begin
  width, height = FastImage.size(
    url,
    timeout: 5,
    raise_on_failure: true
  )

  puts "#{width}x#{height}"
rescue FastImage::ImageFetchFailure => e
  warn "Could not fetch image: #{e.message}"
rescue FastImage::UnknownImageType => e
  warn "Unsupported image: #{e.message}"
end
```

## How it fits into Forem

Forem already proxies images through a CDN, so there was a natural place for this: FastImage slotted into that same step. When we process an image URL, we also get its dimensions.

I added an option, `synchronous_detail_detection`, for whether that happens right away or not. Synchronous detection is the simplest implementation, and since only admins use display units, it's fine for them to wait a moment when they save.

That wouldn't be okay for member posts. Someone could publish a post with 15 images, and doing 15 lookups before the save finishes is how you get a timeout. For that case the detection should happen asynchronously, after the post is saved.

One thing to keep in mind if you do this with user-supplied URLs: it's your server making the request, so it's worth restricting which hosts or networks it will fetch from.

The changes, plus some cleanup I did along the way, are in [this PR](https://github.com/forem/forem/pull/14789).
