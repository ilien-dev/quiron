Authentication is one of those features every app needs and nobody wants to build from scratch. In this tutorial, we'll add GitHub sign-in to a React app using Supabase, with a real user database behind it, in about ten minutes.

By the end, you'll have:

- A React app with "Sign in with GitHub"
- User records stored in a managed Postgres database
- Session handling that survives page refreshes

## What you'll need

- Node.js 18 or later
- A GitHub account
- A free Supabase account

## Step 1: Create the Supabase project

Head to [supabase.com](https://supabase.com), sign in, and create a new project. Give it a name, set a database password, and pick a region close to you. Provisioning takes a minute or two.

Once it's ready, open the project's API settings and copy two values:

- The **Project URL**
- The **anon (publishable) key**

This key is safe to ship in client code. Your data is protected by Row Level Security, not by hiding this key.

## Step 2: Create a GitHub OAuth app

In GitHub, go to **Settings → Developer settings → OAuth Apps → New OAuth App** and fill in:

- **Application name:** anything you like
- **Homepage URL:** `http://localhost:5173`
- **Authorization callback URL:** `https://<your-project-ref>.supabase.co/auth/v1/callback`

The callback points to Supabase, not your app. Supabase handles the OAuth exchange, then redirects the user back to you.

Register the app, then generate a client secret. Copy the **Client ID** and **Client Secret**.

## Step 3: Enable the GitHub provider

Back in the Supabase dashboard, go to **Authentication → Providers → GitHub**. Toggle it on, paste in the Client ID and Client Secret, and save.

While you're in the Authentication section, open **URL Configuration** and confirm that `http://localhost:5173` is set as the Site URL (or added to the redirect allow list). Otherwise, Supabase will refuse to send users back to your local app.

That's the entire back end, with no servers to deploy and no token logic to write.

## Step 4: Scaffold the React app

```bash
npm create vite@latest supabase-github-auth -- --template react
cd supabase-github-auth
npm install @supabase/supabase-js
```

Create a `.env.local` file in the project root:

```bash
VITE_SUPABASE_URL=https://your-project-ref.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
```

Then create `src/supabaseClient.js`:

```js
import { createClient } from '@supabase/supabase-js'

export const supabase = createClient(
  import.meta.env.VITE_SUPABASE_URL,
  import.meta.env.VITE_SUPABASE_ANON_KEY
)
```

## Step 5: Build the auth flow

Replace the contents of `src/App.jsx` with:

```jsx
import { useEffect, useState } from 'react'
import { supabase } from './supabaseClient'

export default function App() {
  const [session, setSession] = useState(null)
  const [loading, setLoading] = useState(true)

  useEffect(() => {
    supabase.auth.getSession().then(({ data: { session } }) => {
      setSession(session)
      setLoading(false)
    })

    const {
      data: { subscription },
    } = supabase.auth.onAuthStateChange((_event, session) => {
      setSession(session)
    })

    return () => subscription.unsubscribe()
  }, [])

  async function signIn() {
    const { error } = await supabase.auth.signInWithOAuth({
      provider: 'github',
      options: { redirectTo: window.location.origin },
    })
    if (error) console.error(error.message)
  }

  async function signOut() {
    const { error } = await supabase.auth.signOut()
    if (error) console.error(error.message)
  }

  if (loading) return <p>Loading...</p>

  if (!session) {
    return (
      <main>
        <h1>Hello, please sign in!</h1>
        <button onClick={signIn}>Sign in with GitHub</button>
      </main>
    )
  }

  const { user } = session

  return (
    <main>
      <img
        src={user.user_metadata.avatar_url}
        alt="avatar"
        width={80}
        style={{ borderRadius: '50%' }}
      />
      <h1>Hello, {user.user_metadata.user_name}</h1>
      <p>{user.email}</p>
      <button onClick={signOut}>Sign out</button>
    </main>
  )
}
```

Three pieces do all the work:

1. **`getSession()`** runs on mount and restores any existing session from local storage, so users stay signed in across refreshes.
2. **`onAuthStateChange()`** subscribes to auth events. When the user returns from GitHub, signs out, or has their token refreshed, the listener fires and the UI updates. The cleanup function unsubscribes when the component unmounts.
3. **`signInWithOAuth()`** redirects the browser to GitHub. After the user approves, GitHub sends them to Supabase, and Supabase sends them back to your `redirectTo` URL with a session.

## Step 6: Try it out

```bash
npm run dev
```

Open `http://localhost:5173` and click **Sign in with GitHub**. Authorize the app, and you'll land back on your page, greeted by your avatar and username.

Now open **Authentication → Users** in the Supabase dashboard. Your account is there, created automatically on first sign-in.

## Where to go from here

You now have a working auth system, and the user's identity is available everywhere Supabase is. Some natural next steps:

- **Protect your data.** Enable Row Level Security on your tables and write policies using `auth.uid()`, such as "users can only read their own rows". The client sends the user's JWT with each request, so the database enforces access for you.
- **Add a profiles table.** Use a Postgres trigger on `auth.users` to create a public profile row whenever someone signs up.
- **Add more providers.** Google, GitLab, Discord, and others follow the same pattern: enable the provider, then change one string in `signInWithOAuth`.
- **Go to production.** Add your deployed URL to the redirect allow list in Supabase, and update the homepage URL in your GitHub OAuth app.

## Wrapping up

In roughly ten minutes and under 70 lines of code, we built full stack authentication: an OAuth flow, persistent sessions, and a Postgres-backed user store. The pattern to remember is small: restore the session on load, listen for changes, and let Supabase handle the rest.
