# State of the API, October/November 2019

APIs continue to be the connective tissue of modern software, and the past couple of months have brought a handful of noteworthy shifts worth catching up on if you've been heads-down shipping features. Here's a roundup of what's been happening in the API world through October and November 2019.

## GraphQL Adoption Keeps Climbing

GraphQL continues to gain ground as an alternative (or complement) to traditional REST APIs. More companies are either fully migrating to GraphQL or adopting a hybrid approach, exposing a GraphQL layer over existing REST services to give front-end teams more flexibility in how they query data.

The appeal is clear: instead of hitting multiple REST endpoints and stitching together responses, or dealing with over-fetching and under-fetching of data, GraphQL lets clients request exactly the shape of data they need in a single request. For teams managing complex front-ends with lots of nested data relationships, this can meaningfully cut down on both network overhead and front-end complexity.

That said, GraphQL isn't a silver bullet. Caching strategies that come for free with REST (thanks to HTTP semantics) require more deliberate design in a GraphQL world, and the learning curve for teams new to the paradigm is real. Still, the tooling ecosystem — Apollo Client, Apollo Server, Relay, and others — has matured significantly, making adoption smoother than it was even a year or two ago.

## API Gateways Becoming Standard Infrastructure

As microservice architectures continue to spread, API gateways have moved from "nice to have" to "standard piece of infrastructure" for a lot of teams. Tools like Kong, AWS API Gateway, and Apigee are increasingly the default entry point for managing authentication, rate limiting, request routing, and monitoring across a fleet of backend services.

This shift makes sense: as the number of individual services grows, having a single, consistent layer to handle cross-cutting concerns (rather than duplicating that logic in every service) becomes essential for maintainability. Expect this trend to keep accelerating as more teams embrace microservices and need a coherent way to manage the resulting API sprawl.

## OpenAPI Specification Continues to Mature

The OpenAPI Specification (formerly Swagger) remains the dominant standard for documenting REST APIs, and its tooling ecosystem keeps expanding. Auto-generated documentation, client SDK generation, and contract testing built on top of OpenAPI specs are becoming increasingly common parts of API development workflows.

Teams are increasingly adopting a "spec-first" approach, where the OpenAPI definition is written before implementation begins, serving as a contract between front-end and back-end teams (or between a company and its external API consumers) before any code gets written. This shift helps catch design issues early and keeps documentation from drifting out of sync with the actual implementation, a problem that's plagued API documentation for years.

## Increased Focus on API Security

With high-profile data breaches continuing to make headlines, API security has become a bigger focus for engineering teams and security researchers alike. OWASP's API Security Top 10 project, which catalogs the most common and impactful API vulnerabilities, has been gaining visibility as teams look for concrete guidance on hardening their APIs against common attack vectors.

Broken object-level authorization, excessive data exposure, and lack of proper rate limiting continue to be among the most common issues found in real-world API security audits. Expect more teams to formalize API security reviews as a standard part of their development lifecycle, rather than treating it as an afterthought.

## Webhooks and Event-Driven APIs

Beyond traditional request/response APIs, there's growing interest in event-driven architectures, where services communicate through events and webhooks rather than direct, synchronous API calls. This pattern decouples services more thoroughly, making systems more resilient to individual service outages and easier to scale independently.

Tools and platforms are increasingly offering built-in webhook support, and standards for structuring event payloads consistently (like CloudEvents) are gaining traction as more companies adopt event-driven patterns at scale.

## API-First Development Philosophy

More companies are adopting an "API-first" mindset, where the API is treated as a primary product rather than an implementation detail supporting a specific front-end. This reflects the reality that a single API often needs to support multiple consumers — web apps, mobile apps, third-party integrations, internal tooling — and designing it as a first-class product from the start leads to more flexible, durable systems down the line.

This philosophy also ties closely into the growth of API marketplaces and developer portals, as more companies treat their APIs as products meant to be discovered, documented, and consumed by external developers, not just internal teams.

## Wrapping Up

The API landscape continues to evolve at a steady clip. GraphQL adoption keeps growing alongside (not necessarily replacing) REST, API gateways are becoming standard infrastructure for managing service sprawl, security is getting more deserved attention, and event-driven patterns are gaining traction as systems grow more distributed.

As we head toward the end of the year, it's worth keeping an eye on how these trends continue to develop, and considering where your own team's API strategy might benefit from adopting some of these emerging patterns and tools.
