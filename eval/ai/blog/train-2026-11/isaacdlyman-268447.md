Every year the same question fills my feed: "What should I build for my portfolio?" Tutorials are everywhere, but the gap between finishing a course and showing something employers care about is real. This post collects project ideas for 2020, grouped by experience level, plus a few tips on presenting them.

## What Makes a Portfolio Project Good?

Before the list, a quick filter. A strong project usually has:

- **A real problem behind it.** Even a tiny one. "I built this because I kept forgetting X" beats "I followed a tutorial."
- **A live demo.** Recruiters rarely clone repos. A link they can click gets far more attention.
- **A readable README.** Explain what it does, how to run it, and what you learned.
- **Some depth.** Authentication, persistence, testing, or an API integration shows you can go beyond a static page.

If a project hits three of those four, it's worth showing.

## Beginner Ideas

Keep the scope small and finish things. A deployed small app is worth more than an abandoned big one.

1. **Personal landing page.** Plain HTML, CSS, and a little JavaScript. Make it responsive and accessible. This is also your portfolio's home.
2. **Weather app.** Call a public API, handle loading and error states, and let users search by city.
3. **To-do app with local storage.** A classic for a reason. Add filtering, due dates, and drag-and-drop to make it your own.
4. **Recipe finder.** Fetch from a free recipe API and let users save favorites.
5. **Quiz game.** Great for practicing state, timers, and scoring logic.

## Intermediate Ideas

Now add a backend, a database, and users.

1. **Expense tracker.** Authentication, CRUD operations, and charts for monthly spending. Data visualization libraries like Chart.js make it look impressive.
2. **Blog platform.** Markdown support, comments, and tags. Build the API and the front end separately to practice architecture.
3. **Real-time chat app.** WebSockets (Socket.io is a friendly start) teach you a lot about events and state across clients.
4. **Job application tracker.** Useful to you right now, and you can use it during your own job search. Kanban-style boards teach drag-and-drop and state management.
5. **Browser extension.** Block distracting sites, save highlights, or change a page's style. Extensions are small, practical, and uncommon in portfolios.

## Advanced Ideas

These show you can handle complexity and make design decisions.

1. **Full-stack SaaS clone.** Build a small version of a tool you like, with subscriptions via Stripe's test mode, role-based access, and email notifications.
2. **Progressive Web App.** Offline support, service workers, and installability. Turn one of your earlier projects into a PWA.
3. **Open-source contribution.** Not strictly a project, but merged pull requests on a known repository are strong proof you can work in an existing codebase.
4. **Machine learning demo.** Train a simple model, such as sentiment analysis or image classification, and expose it through a web interface.
5. **CI/CD pipeline project.** Take any app and add automated tests, linting, and deployment through GitHub Actions or a similar tool. Employers love seeing this.

## Ideas That Stand Out

If you want something memorable, try these angles:

- **Build for a local business or nonprofit.** Real clients and real feedback are rare among juniors.
- **Solve a problem in your previous career.** A former teacher building a grading tool, or a former nurse building a shift planner, brings unique insight.
- **Clone, then improve.** Rebuild a popular app, then add one feature the original lacks and explain why.
- **Make a developer tool.** A CLI, a VS Code extension, or a small library published on npm shows you think about other developers.

## Presenting Your Portfolio

The projects are only half the work. How you show them matters.

- **Pick three to five.** Quality over quantity. Remove weak or unfinished work.
- **Tell the story.** For each project, write what the problem was, which tools you chose and why, and what you'd do differently.
- **Show the code's quality.** Clean commits, meaningful names, and some tests all signal professionalism.
- **Write about it.** A post on dev.to about what you learned doubles as content for your portfolio and helps others.
- **Keep it alive.** Fix broken links, update dependencies, and retire projects that no longer reflect your skills.

## Final Thoughts

You don't need a groundbreaking idea. You need to pick something, build it, ship it, and explain it well. Start with the smallest version that works, deploy it early, and improve it in public. By the end of 2020, you could have a portfolio that tells a clear story about how you think and grow as a developer.
