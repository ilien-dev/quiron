# Forem Hacktoberfest: Let's Internationalize!

Every developer who has searched for an answer at 2 a.m. knows the feeling of finding exactly the post they needed. Now imagine that post is written in a language you don't read well. The knowledge is there, but it's locked behind a barrier that has nothing to do with your skill.

That's the problem internationalization (often shortened to **i18n**, because there are 18 letters between the "i" and the "n") is meant to solve. For Forem, the open source platform behind DEV, it's also one of the most useful ways to contribute during Hacktoberfest.

## What Is Internationalization?

Internationalization is the work of preparing software so it can be presented in many languages and regions without rewriting the code each time. It involves:

- **Separating text from code.** Strings like "Save draft" or "Your post has been published" live in locale files, not hardcoded in components.
- **Handling formats.** Dates, numbers, currencies, and plural forms differ across locales. "1 comment" and "2 comments" are simple in English, but many languages have several plural categories.
- **Supporting right-to-left text.** Arabic and Hebrew change layout direction, which affects spacing, icons, and alignment.

Localization (l10n) is the companion task: actually translating those strings and adapting content for a specific audience. Internationalization builds the room, and localization furnishes it.

## Why It Matters for Forem

DEV's community is global. Developers read and write in dozens of languages, and a community platform that only speaks English leaves many of its members as second-class readers. Translated interfaces make onboarding easier, lower the barrier for new contributors, and let more people participate in discussions on their own terms.

Forem's codebase is built to support this work. The strings are organized into locale files, so a contributor doesn't need to understand the whole application to make a meaningful change. You can translate a single file, verify it in the running app, and open a pull request in an afternoon.

## Where to Start

If you're new to Forem, here's a practical path:

1. **Read the contributing guide.** The repository's documentation explains local setup, coding conventions, and how to run the app. Follow it closely, since a working local environment makes everything else easier.
2. **Pick a language you know well.** Translation quality depends on fluency and cultural context. Choose one where you can judge whether a phrase sounds natural, not just whether it's technically correct.
3. **Check what's already translated.** Look at existing locale files to see which strings are missing or outdated. Opening an issue to claim a section helps avoid duplicated work.
4. **Start small.** A few dozen strings in a navigation menu or settings page is a great first pull request. Small, focused changes are easier to review and merge.
5. **Test in context.** Run the app with your language selected and look for truncated text, awkward line breaks, or placeholders that didn't render. A translation can be correct in isolation and still break the layout.

## Tips for Good Translations

- **Keep placeholders intact.** Variables like `{username}` or `%{count}` must stay exactly as they are. Only move them if the grammar of your language requires it.
- **Preserve tone.** Forem's voice is friendly and direct. Translate the intent, not each word.
- **Ask when unsure.** If a term is ambiguous, mention it in the pull request. Reviewers and other translators would rather answer a question than fix a subtle mistake later.
- **Don't translate brand names or code terms** unless the project's guidelines say otherwise.

## Beyond Translation

Internationalization also includes reviewing the code. You can help by:

- Finding hardcoded strings that should be moved into locale files
- Reporting date or number formats that don't respect the selected locale
- Testing right-to-left layouts and filing issues for anything that breaks
- Improving documentation so future contributors know how to add a language

These tasks suit developers who haven't contributed to open source before, as well as experienced engineers who want to work on frontend architecture.

## An Invitation

Hacktoberfest is a good reason to start, but the work doesn't stop in October. Languages evolve, new features need new strings, and every improvement makes the community more welcoming to someone who has been reading in a second language.

If you speak a language that isn't yet fully represented on DEV, consider this your invitation. Open the repository, find a file, and make one string better. Then tell someone in your community about it. That's how a global platform gets built: one translated sentence at a time.

Happy hacking, and happy translating!
