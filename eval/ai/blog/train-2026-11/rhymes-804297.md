Rails has shipped unobtrusive Ajax support for a long time. Add `data-remote="true"` to a form or link and `rails-ujs` sends the request with `fetch`-style XHR, attaches the CSRF token, and fires DOM events as the request progresses. Stimulus gives you a clean, conventional place to put the JavaScript that reacts to those events.

The two fit together well. `rails-ujs` handles the request, and Stimulus handles what happens before and after it. This post walks through how to wire them up, with a comments form as the running example.

> **A note on Turbo:** Since Rails 7, new apps default to Turbo, and Turbo Drive and Turbo Streams cover many of the same use cases. Plenty of production apps still run on `rails-ujs`, though, and the patterns below are useful there. At the end there's a short section on mapping these ideas to Turbo.

## The events rails-ujs gives you

When you submit a remote form or click a remote link, `rails-ujs` dispatches these custom events on the element:

| Event | When it fires | `event.detail` |
|---|---|---|
| `ajax:before` | Before anything happens. Cancel it to stop the request. | — |
| `ajax:beforeSend` | Before the XHR is sent. Cancel it to abort. | `[xhr, options]` |
| `ajax:send` | Once the request is sent | `[xhr]` |
| `ajax:success` | On a 2xx response | `[response, status, xhr]` |
| `ajax:error` | On a non-2xx response | `[response, status, xhr]` |
| `ajax:complete` | After success or error | `[xhr, status]` |
| `ajax:stopped` | When `ajax:before` or `ajax:beforeSend` was cancelled | — |

All of these bubble up the DOM. Stimulus actions are DOM event listeners, so you can hook into these events with `data-action` like any other event.

## Setup

If you're on importmaps:

```bash
bin/importmap pin @rails/ujs
```

Then start it in `app/javascript/application.js`:

```js
import Rails from "@rails/ujs"
Rails.start()

import "controllers"
```

With jsbundling or webpacker, run `yarn add @rails/ujs` and use the same imports. Stimulus is set up the usual way, either with `bin/rails stimulus:install` or with `@hotwired/stimulus` and an `application.js` that registers your controllers.

## Example: posting a comment without a page reload

### The Rails side

A standard controller that responds with an HTML partial on success and JSON errors on failure:

```ruby
# app/controllers/comments_controller.rb
class CommentsController < ApplicationController
  def create
    @post = Post.find(params[:post_id])
    @comment = @post.comments.build(comment_params)

    if @comment.save
      render partial: "comments/comment", locals: { comment: @comment }, status: :created
    else
      render json: { errors: @comment.errors.full_messages }, status: :unprocessable_entity
    end
  end

  private

  def comment_params
    params.require(:comment).permit(:body)
  end
end
```

The form is a remote form with a Stimulus controller attached:

```erb
<%# app/views/posts/show.html.erb %>
<div data-controller="comments">
  <ul data-comments-target="list">
    <%= render @post.comments %>
  </ul>

  <%= form_with model: [@post, Comment.new],
        data: {
          remote: true,
          comments_target: "form",
          action: "ajax:beforeSend->comments#start ajax:success->comments#added ajax:error->comments#failed ajax:complete->comments#finish"
        } do |f| %>
    <div data-comments-target="errors" hidden></div>
    <%= f.text_area :body, data: { comments_target: "body" } %>
    <%= f.submit "Post comment", data: { comments_target: "submit" } %>
  <% end %>
</div>
```

Two details matter here:

1. **`data: { remote: true }` is explicit.** `form_with` generated remote forms by default in Rails 5.1–6.0, but newer apps set `form_with_generates_remote_forms = false`. Being explicit means the form behaves the same everywhere.
2. **The Stimulus actions use the `event->controller#method` form.** The default event for a form is `submit`, so you have to name the `ajax:*` events yourself.

### The Stimulus side

```js
// app/javascript/controllers/comments_controller.js
import { Controller } from "@hotwired/stimulus"

export default class extends Controller {
  static targets = ["list", "form", "body", "submit", "errors"]

  start() {
    this.submitTarget.disabled = true
    this.clearErrors()
  }

  added(event) {
    const [_data, _status, xhr] = event.detail
    this.listTarget.insertAdjacentHTML("beforeend", xhr.responseText)
    this.formTarget.reset()
    this.bodyTarget.focus()
  }

  failed(event) {
    const [data, _status, xhr] = event.detail

    if (xhr.status === 422 && data.errors) {
      this.showErrors(data.errors)
    } else {
      this.showErrors(["Something went wrong. Please try again."])
    }
  }

  finish() {
    this.submitTarget.disabled = false
  }

  showErrors(messages) {
    this.errorsTarget.innerHTML = messages
      .map((m) => `<p>${this.escape(m)}</p>`)
      .join("")
    this.errorsTarget.hidden = false
  }

  clearErrors() {
    this.errorsTarget.innerHTML = ""
    this.errorsTarget.hidden = true
  }

  escape(text) {
    const div = document.createElement("div")
    div.textContent = text
    return div.innerHTML
  }
}
```

### Why `xhr.responseText` and not `data`?

`rails-ujs` parses the response based on its `Content-Type`. JSON becomes a JavaScript object, which is what you want in `failed`. HTML is parsed with `DOMParser` into a full `Document`, so `data` in `added` is a document rather than a string. You could pull the `<li>` out of `data.body`, but `xhr.responseText` gives you the raw markup for `insertAdjacentHTML` and is easier to work with.

### Why not use `data-disable-with`?

You can. `rails-ujs` will disable the button and swap its label for you. I put it in the controller to show the `ajax:beforeSend` / `ajax:complete` pair, because that pattern comes up often for things like spinners, `aria-busy`, or dimming a whole section. Use whichever fits.

## Listening on a parent element

Because the events bubble, the Stimulus action doesn't need to be on the form. Suppose each comment has a remote "Delete" link:

```erb
<%# app/views/comments/_comment.html.erb %>
<li id="<%= dom_id(comment) %>">
  <%= comment.body %>
  <%= link_to "Delete", [comment.post, comment],
        data: { remote: true, method: :delete, confirm: "Delete this comment?" } %>
</li>
```

You can catch every one of those on the list:

```erb
<ul data-comments-target="list"
    data-action="ajax:success->comments#removed">
```

```js
removed(event) {
  event.target.closest("li").remove()
}
```

`event.target` is the link that fired the request, so you know which comment to remove. Comments added later through `insertAdjacentHTML` work as well, since the listener sits on the parent. You don't need to re-bind anything.

One caveat: the form's `ajax:success` also bubbles past the list if the form is inside it. In the markup above the form is a sibling of the list, so it's fine. If your layout nests them, check `event.target` in the handler or use the `:self` action option (`ajax:success->comments#removed:self`) to ignore events from descendants.

## Cancelling a request from Stimulus

`ajax:before` and `ajax:beforeSend` can be cancelled. That makes them a good place for client-side validation that you want to keep out of the server round trip:

```erb
data-action="ajax:before->comments#validate ajax:beforeSend->comments#start ..."
```

```js
validate(event) {
  if (this.bodyTarget.value.trim() === "") {
    event.preventDefault()
    this.showErrors(["Comment can't be blank"])
  }
}
```

When `ajax:before` is cancelled, `rails-ujs` fires `ajax:stopped` and sends nothing.

## Submitting a remote form programmatically

A common need is to autosave a form when a field changes. Calling `form.submit()` doesn't work, because it skips the `submit` event that `rails-ujs` listens for, so you get a full page navigation. Use `requestSubmit()` instead, which goes through the normal submit flow:

```js
// app/javascript/controllers/autosave_controller.js
import { Controller } from "@hotwired/stimulus"

export default class extends Controller {
  static values = { delay: { type: Number, default: 500 } }

  save() {
    clearTimeout(this.timeout)
    this.timeout = setTimeout(() => this.element.requestSubmit(), this.delayValue)
  }

  disconnect() {
    clearTimeout(this.timeout)
  }
}
```

```erb
<%= form_with model: @draft, data: { remote: true, controller: "autosave",
      action: "input->autosave#save" } do |f| %>
```

`requestSubmit()` works in all current browsers. If you have to support something older, `Rails.fire(form, "submit")` from `@rails/ujs` does the same job.

## Making requests directly with `Rails.ajax`

Sometimes there's no form or link, like when you're saving the new order after a drag-and-drop reorder. `rails-ujs` exposes the same request machinery as `Rails.ajax`, and it still handles the CSRF token for you:

```js
import { Controller } from "@hotwired/stimulus"
import Rails from "@rails/ujs"

export default class extends Controller {
  static values = { url: String }

  reorder() {
    const ids = [...this.element.children].map((li) => li.dataset.id)
    const data = new FormData()
    ids.forEach((id) => data.append("ids[]", id))

    Rails.ajax({
      type: "PATCH",
      url: this.urlValue,
      data: data,
      success: () => this.element.classList.remove("is-dirty"),
      error: (_data, _status, xhr) => console.error("Reorder failed", xhr.status),
    })
  }
}
```

The `success`, `error`, and `complete` callbacks get the same arguments as the event `detail` arrays above, so the handling code looks the same in both places.

## If you're moving to Turbo

The structure carries over to Turbo almost directly. Only the event names change:

- `ajax:beforeSend` → `turbo:submit-start`
- `ajax:success` / `ajax:error` / `ajax:complete` → `turbo:submit-end`, with `event.detail.success` and `event.detail.fetchResponse`
- `data-remote="true"` → nothing; Turbo handles forms by default

In a Turbo app you'll often drop the manual DOM insertion and return a Turbo Stream that appends the comment. The Stimulus controller then only handles UI state like disabling the button, clearing the form, and focusing the field. That's a good split to aim for even with `rails-ujs`.

## Wrapping up

The pattern is short:

1. Let `rails-ujs` make the request with `data-remote`, so CSRF, method spoofing, and confirmation dialogs are handled for you.
2. Listen for `ajax:*` events with Stimulus actions using the `event->controller#method` syntax.
3. Read `event.detail` to get the response, and use `xhr.responseText` when you need raw HTML.
4. Put listeners on a parent element when you have many requesting elements, and rely on bubbling.
5. Use `requestSubmit()` or `Rails.ajax` when you need to start a request from JavaScript.

This keeps your Rails controllers ordinary and your JavaScript small and organized by behavior, and it gives you a clear path to Turbo when you're ready.
