# How to Build a Full Stack NFT Marketplace - V2 (2022)

An NFT marketplace is a great project for learning Web3. You end up touching smart contracts and wallet authentication, and you also get to work with decentralized storage and a modern frontend.

In this guide we'll build a full stack NFT marketplace where users can:

- Connect an Ethereum wallet
- Mint NFTs with images and metadata
- List NFTs for sale
- Browse available NFTs
- Purchase NFTs
- View owned and created assets

The stack is Solidity, Hardhat, Polygon, Next.js, ethers.js and IPFS.

> This tutorial uses the Web3 tooling available in 2022. Some package APIs may differ in newer versions.

### How the pieces fit together

There are three main layers to the app:

1. **Smart contract:** Creates NFTs, stores listings, and processes sales.
2. **IPFS:** Stores NFT images and metadata.
3. **Next.js application:** Provides the interface and communicates with the blockchain.

The NFT itself uses the ERC-721 standard. The marketplace listings live in the smart contract, so we don't need a traditional backend or database at all.

## Setting up the project

To get started, create a new Next.js app:

```bash
npx create-next-app nft-marketplace
cd nft-marketplace
```

Next, install the dependencies we'll need:

```bash
npm install ethers@5 web3modal axios
npm install ipfs-http-client
npm install --save-dev hardhat @nomiclabs/hardhat-ethers
npm install @openzeppelin/contracts
```

Then initialize Hardhat:

```bash
npx hardhat
```

When it prompts you, choose __Create a basic sample project__.

You should now have `contracts`, `scripts` and `test` directories sitting next to the Next.js app.

## The smart contract

Create a new file named __contracts/NFTMarketplace.sol__:

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.4;

import "@openzeppelin/contracts/utils/Counters.sol";
import "@openzeppelin/contracts/token/ERC721/extensions/ERC721URIStorage.sol";
import "@openzeppelin/contracts/security/ReentrancyGuard.sol";

contract NFTMarketplace is ERC721URIStorage, ReentrancyGuard {
    using Counters for Counters.Counter;

    Counters.Counter private tokenIds;
    Counters.Counter private soldItems;

    uint256 public listingPrice = 0.025 ether;
    address payable private marketplaceOwner;

    struct MarketItem {
        uint256 tokenId;
        address payable seller;
        address payable owner;
        uint256 price;
        bool sold;
    }

    mapping(uint256 => MarketItem) private marketItems;

    event MarketItemCreated(
        uint256 indexed tokenId,
        address seller,
        address owner,
        uint256 price,
        bool sold
    );

    constructor() ERC721("Marketplace Token", "MKT") {
        marketplaceOwner = payable(msg.sender);
    }

    function createToken(
        string memory tokenURI,
        uint256 price
    ) public payable returns (uint256) {
        tokenIds.increment();
        uint256 newTokenId = tokenIds.current();

        _mint(msg.sender, newTokenId);
        _setTokenURI(newTokenId, tokenURI);
        createMarketItem(newTokenId, price);

        return newTokenId;
    }

    function createMarketItem(
        uint256 tokenId,
        uint256 price
    ) private {
        require(price > 0, "Price must be greater than zero");
        require(
            msg.value == listingPrice,
            "Submit the required listing price"
        );

        marketItems[tokenId] = MarketItem(
            tokenId,
            payable(msg.sender),
            payable(address(this)),
            price,
            false
        );

        _transfer(msg.sender, address(this), tokenId);

        emit MarketItemCreated(
            tokenId,
            msg.sender,
            address(this),
            price,
            false
        );
    }
}
```

When an NFT gets listed, ownership moves over to the marketplace contract, and the contract keeps the NFT in escrow until somebody buys it.

Next, let's add the function for buying an item:

```solidity
function createMarketSale(uint256 tokenId) public payable nonReentrant {
    MarketItem storage item = marketItems[tokenId];

    require(msg.value == item.price, "Submit the asking price");
    require(!item.sold, "Item has already been sold");

    item.seller.transfer(msg.value);
    transferFrom(address(this), msg.sender, tokenId);

    item.owner = payable(msg.sender);
    item.sold = true;
    soldItems.increment();

    marketplaceOwner.transfer(listingPrice);
}
```

The `nonReentrant` modifier protects this transaction from reentrancy attacks while the funds and the ownership are being transferred.

Now we need a way to load the NFTs that haven't sold yet:

```solidity
function fetchMarketItems() public view returns (MarketItem[] memory) {
    uint256 totalItems = tokenIds.current();
    uint256 unsoldCount = totalItems - soldItems.current();
    uint256 index = 0;

    MarketItem[] memory items = new MarketItem[](unsoldCount);

    for (uint256 i = 1; i <= totalItems; i++) {
        if (marketItems[i].owner == address(this)) {
            items[index] = marketItems[i];
            index++;
        }
    }

    return items;
}
```

You can write similar view functions for the NFTs a user owns and the ones they created:

```solidity
function fetchMyNFTs() public view returns (MarketItem[] memory) {
    uint256 totalItems = tokenIds.current();
    uint256 itemCount = 0;
    uint256 index = 0;

    for (uint256 i = 1; i <= totalItems; i++) {
        if (marketItems[i].owner == msg.sender) {
            itemCount++;
        }
    }

    MarketItem[] memory items = new MarketItem[](itemCount);

    for (uint256 i = 1; i <= totalItems; i++) {
        if (marketItems[i].owner == msg.sender) {
            items[index] = marketItems[i];
            index++;
        }
    }

    return items;
}
```

### Configuring Hardhat

Update __hardhat.config.js__:

```javascript
require("@nomiclabs/hardhat-ethers");

module.exports = {
  solidity: "0.8.4",
  networks: {
    hardhat: {
      chainId: 1337,
    },
  },
};
```

Compile the contract:

```bash
npx hardhat compile
```

Then create __scripts/deploy.js__:

```javascript
async function main() {
  const Marketplace = await ethers.getContractFactory("NFTMarketplace");
  const marketplace = await Marketplace.deploy();

  await marketplace.deployed();

  console.log("Marketplace deployed to:", marketplace.address);
}

main()
  .then(() => process.exit(0))
  .catch((error) => {
    console.error(error);
    process.exit(1);
  });
```

Start a local blockchain:

```bash
npx hardhat node
```

And in another terminal window, deploy the contract:

```bash
npx hardhat run scripts/deploy.js --network localhost
```

Copy the address the contract was deployed to. We'll need it in the frontend.

## The frontend

Create a file named __config.js__ in the root of the project:

```javascript
export const marketplaceAddress =
  "YOUR_DEPLOYED_CONTRACT_ADDRESS";
```

Hardhat puts the contract ABI in the `artifacts` directory. Import the artifact anywhere the frontend needs to create a contract instance.

For a read-only connection, a JSON-RPC provider is all you need:

```javascript
import { ethers } from "ethers";
import NFTMarketplace from "./artifacts/contracts/NFTMarketplace.sol/NFTMarketplace.json";
import { marketplaceAddress } from "./config";

const provider = new ethers.providers.JsonRpcProvider(
  "http://127.0.0.1:8545"
);

const contract = new ethers.Contract(
  marketplaceAddress,
  NFTMarketplace.abi,
  provider
);
```

Sending transactions is different because you need a wallet signer, so let's make a small helper for that:

```javascript
import Web3Modal from "web3modal";

async function getSignedContract() {
  const web3Modal = new Web3Modal();
  const connection = await web3Modal.connect();
  const provider = new ethers.providers.Web3Provider(connection);
  const signer = provider.getSigner();

  return new ethers.Contract(
    marketplaceAddress,
    NFTMarketplace.abi,
    signer
  );
}
```

Web3Modal opens the interface for picking a wallet, and ethers.js wraps whichever wallet the user picked as a signer.

### Uploading to IPFS

An NFT's `tokenURI` usually points to a JSON document with its name, description and image URL. We can store both the image and the metadata on IPFS.

Set up an IPFS client with whichever IPFS pinning service you like:

```javascript
import { create as createIPFSClient } from "ipfs-http-client";

const client = createIPFSClient({
  url: "YOUR_IPFS_API_ENDPOINT",
  headers: {
    authorization: "YOUR_AUTHORIZATION_HEADER",
  },
});
```

In production you should never expose a private IPFS API secret in browser code. Put the uploads behind a server-side API route, or use a provider that supports safely scoped uploads from the client.

Here's the function that uploads the selected image:

```javascript
async function uploadImage(event) {
  const file = event.target.files[0];
  if (!file) return;

  const result = await client.add(file);
  const imageUrl = `https://ipfs.io/ipfs/${result.path}`;

  setFileUrl(imageUrl);
}
```

And this one uploads the metadata:

```javascript
async function createMetadata(name, description, image) {
  const data = JSON.stringify({
    name,
    description,
    image,
  });

  const result = await client.add(data);
  return `https://ipfs.io/ipfs/${result.path}`;
}
```

### Minting and listing an NFT

The minting form collects a name, description, price and image. Once everything is uploaded, we call `createToken`:

```javascript
async function createNFT() {
  const metadataUrl = await createMetadata(
    formInput.name,
    formInput.description,
    fileUrl
  );

  const contract = await getSignedContract();
  const price = ethers.utils.parseUnits(formInput.price, "ether");
  const listingPrice = await contract.listingPrice();

  const transaction = await contract.createToken(
    metadataUrl,
    price,
    {
      value: listingPrice,
    }
  );

  await transaction.wait();
}
```

That one contract call is doing two blockchain operations: it mints the token, and it puts the token into marketplace escrow.

I'd also validate the form before submitting it. A missing image or an invalid price should never make it as far as the wallet confirmation.

### Showing the NFTs in the marketplace

To render the marketplace, we load the unsold items and then resolve the metadata for each token:

```javascript
async function loadNFTs() {
  const data = await contract.fetchMarketItems();

  const items = await Promise.all(
    data.map(async (item) => {
      const tokenUri = await contract.tokenURI(item.tokenId);
      const metadata = await axios.get(tokenUri);

      return {
        tokenId: item.tokenId.toNumber(),
        seller: item.seller,
        owner: item.owner,
        price: ethers.utils.formatUnits(
          item.price.toString(),
          "ether"
        ),
        image: metadata.data.image,
        name: metadata.data.name,
        description: metadata.data.description,
      };
    })
  );

  setNfts(items);
}
```

Then we render the data with regular React components:

```jsx
{nfts.map((nft) => (
  <article key={nft.tokenId}>
    <img src={nft.image} alt={nft.name} />
    <h2>{nft.name}</h2>
    <p>{nft.description}</p>
    <strong>{nft.price} ETH</strong>
    <button onClick={() => buyNFT(nft)}>Buy</button>
  </article>
))}
```

### Buying an NFT

Buying calls `createMarketSale` and sends the exact asking price:

```javascript
async function buyNFT(nft) {
  const contract = await getSignedContract();
  const price = ethers.utils.parseUnits(nft.price, "ether");

  const transaction = await contract.createMarketSale(
    nft.tokenId,
    {
      value: price,
    }
  );

  await transaction.wait();
  await loadNFTs();
}
```

Once the transaction is confirmed, the seller gets paid and the buyer gets the NFT. The item also drops out of the available listings.

## Deploying to Polygon

Local development is really nice for testing things quickly, but a public marketplace has to run on a shared network. Polygon has low transaction fees and works with Ethereum tooling.

Add Polygon's test network to your Hardhat config with an RPC provider and a wallet to deploy from:

```javascript
require("dotenv").config();

module.exports = {
  solidity: "0.8.4",
  networks: {
    polygonTestnet: {
      url: process.env.POLYGON_RPC_URL,
      accounts: [process.env.PRIVATE_KEY],
    },
  },
};
```

Put the credentials in __.env__:

```text
POLYGON_RPC_URL=YOUR_RPC_URL
PRIVATE_KEY=YOUR_PRIVATE_KEY
```

Don't ever commit this file! Add it to __.gitignore__, fund the deployment wallet with some test tokens, and deploy:

```bash
npx hardhat run scripts/deploy.js --network polygonTestnet
```

Then swap the local contract address in __config.js__ for the new one. Your wallet and the frontend both have to be on the same network too.

## Before you use this for anything real

This marketplace is a good foundation for learning, but a production contract needs more work. Before it handles assets with real value, you'll want to:

- Write tests for minting, buying, permissions, and failed transactions.
- Use a well-defined fee and royalty model.
- Add events for every important state transition.
- Avoid unbounded loops as the collection grows.
- Consider indexing events with a service such as The Graph.
- Pin IPFS content through multiple reliable providers.
- Handle rejected transactions and network mismatches in the UI.
- Obtain an independent smart-contract security audit.

Upgradable contracts can be useful, but they come with governance and security tradeoffs. Immutable contracts are often easier for users to reason about.

From here you could add auctions, creator royalties, collection pages, search, activity feeds and better wallet support.
