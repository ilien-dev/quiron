# Using FastImage to detect image dimensions in Ruby

If your app accepts image URLs, there's a good chance you need to know how big the image is before you download or process the whole thing. Maybe you want to validate a remote image, work out its aspect ratio, save space for it in a layout, or reject files that are too small.

The `fastimage` gem is built for exactly this. It reads only the part of the file it needs to find the dimensions, which is a lot cheaper than pulling down the complete image and opening it with an image-processing library.

## Getting it installed

Add the gem to your `Gemfile`:

```ruby
gem "fastimage"
```

Then install it:

```bash
bundle install
```

Or install it directly:

```bash
gem install fastimage
```

If you aren't using Bundler's automatic loading, require it yourself:

```ruby
require "fastimage"
```

## Reading dimensions

The main API is `FastImage.size`. Hand it an image URL and you get back an array with the width and the height:

```ruby
url = "https://example.com/images/header.jpg"

width, height = FastImage.size(url)

puts "Width: #{width}px"
puts "Height: #{height}px"
```

For a 1200-by-630 image, that gives you:

```ruby
[1200, 630]
```

The trick is that common image formats keep their dimensions in metadata near the start of the file. FastImage asks for enough data to find that metadata and stops there, so it never fetches every byte.

You can ask for the format too:

```ruby
type = FastImage.type(url)

puts type
# => :jpeg
```

It supports JPEG, PNG, GIF, BMP, TIFF, ICO, WebP and SVG, among others.

And it isn't limited to remote URLs. It'll happily inspect a file on disk, so your code gets the same interface whether the image is local or remote:

```ruby
width, height = FastImage.size("public/uploads/avatar.png")

puts "#{width}x#{height}"
```

## Aspect ratio and orientation

Once you have the dimensions, the aspect ratio is simple:

```ruby
width, height = FastImage.size(url)

if width && height
  aspect_ratio = width.to_f / height
  puts aspect_ratio.round(2)
end
```

Don't skip the `to_f` on `width`. It makes the intent obvious and avoids integer-division surprises in older Ruby versions.

You can classify the image from there:

```ruby
orientation =
  if width > height
    :landscape
  elsif height > width
    :portrait
  else
    :square
  end
```

That comes in handy when you're picking thumbnails or deciding how an image should sit in a responsive layout.

## When things go wrong

Remote resources are unreliable. A URL might be down or slow. It could also point at something that isn't a supported image at all. By default `FastImage.size` can just return `nil` when it can't work out the dimensions:

```ruby
dimensions = FastImage.size(url)

if dimensions
  width, height = dimensions
  puts "#{width}x#{height}"
else
  puts "Unable to read image dimensions"
end
```

If you'd rather deal with exceptions, turn on `raise_on_failure`:

```ruby
begin
  width, height = FastImage.size(
    url,
    timeout: 5,
    raise_on_failure: true
  )

  puts "#{width}x#{height}"
rescue FastImage::ImageFetchFailure => e
  warn "Could not fetch image: #{e.message}"
rescue FastImage::UnknownImageType => e
  warn "Unsupported image: #{e.message}"
end
```

Set that timeout. Without it, a slow server can tie up your application indefinitely.

A small helper turns all of this into validation you can reuse:

```ruby
def large_enough?(url, minimum_width:, minimum_height:)
  width, height = FastImage.size(url, timeout: 5)

  width >= minimum_width && height >= minimum_height
rescue TypeError
  false
end
```

And you call it like this:

```ruby
large_enough?(
  "https://example.com/photo.jpg",
  minimum_width: 800,
  minimum_height: 600
)
```

One thing to keep in mind with user-supplied URLs: it's *your* server making the request. Restrict the hosts or network destinations you allow, or you're opening yourself up to server-side request forgery.

FastImage is a focused tool. It won't resize, optimize or transform anything. But when dimensions or the format are all you need, it saves you the cost and the complexity of a full image-processing pipeline, and I think that's a good trade.
