# Using FastImage to detect image dimensions in Ruby

Applications that accept image URLs often need to know an image's width and height before downloading or processing the entire file. Maybe you want to validate a remote image, calculate its aspect ratio, reserve space for it in a layout, or reject files that are too small.

Ruby's `fastimage` gem does exactly this. It reads only the part of the file that holds the size, which is much more efficient than downloading the complete image and opening it with an image-processing library.

## Installing FastImage

Add the gem to your `Gemfile`:

```ruby
gem "fastimage"
```

Then install it:

```bash
bundle install
```

Or install it directly:

```bash
gem install fastimage
```

If you aren't using Bundler's automatic loading, require it:

```ruby
require "fastimage"
```

## Reading dimensions from a URL

The main call is `FastImage.size`. Give it an image URL and you get back an array with the width and height:

```ruby
url = "https://example.com/images/header.jpg"

width, height = FastImage.size(url)

puts "Width: #{width}px"
puts "Height: #{height}px"
```

For a 1200-by-630 image, you get:

```ruby
[1200, 630]
```

This works because common image formats store their size in metadata near the beginning of the file. FastImage requests enough data to find it, and the rest of the file is never fetched.

You can also ask for the format:

```ruby
type = FastImage.type(url)

puts type
# => :jpeg
```

Supported formats include JPEG, PNG, GIF, BMP, TIFF, ICO, WebP and SVG.

## Reading local images

It isn't only for URLs. It can read files on disk too:

```ruby
width, height = FastImage.size("public/uploads/avatar.png")

puts "#{width}x#{height}"
```

That gives your code one consistent interface whether an image is local or remote.

## Calculating an aspect ratio

Once you have the width and height, it is a single division:

```ruby
width, height = FastImage.size(url)

if width && height
  aspect_ratio = width.to_f / height
  puts aspect_ratio.round(2)
end
```

The `to_f` on `width` matters. It makes it clear you want a float, and it avoids integer division surprises in older Ruby versions.

You can also sort the image by shape:

```ruby
orientation =
  if width > height
    :landscape
  elsif height > width
    :portrait
  else
    :square
  end
```

That's handy when you're selecting thumbnails or deciding how an image should appear in a responsive layout.

## When it fails

Remote resources are unreliable. A URL might be unavailable or slow, or it might point to something that isn't a supported image. By default, `FastImage.size` can return `nil` when it can't work out the size:

```ruby
dimensions = FastImage.size(url)

if dimensions
  width, height = dimensions
  puts "#{width}x#{height}"
else
  puts "Unable to read image dimensions"
end
```

If you'd rather get an exception, turn on `raise_on_failure`:

```ruby
begin
  width, height = FastImage.size(
    url,
    timeout: 5,
    raise_on_failure: true
  )

  puts "#{width}x#{height}"
rescue FastImage::ImageFetchFailure => e
  warn "Could not fetch image: #{e.message}"
rescue FastImage::UnknownImageType => e
  warn "Unsupported image: #{e.message}"
end
```

The timeout stops a slow server from tying up your application indefinitely.

## Checking that an image is big enough

A small helper turns this into a check you can reuse:

```ruby
def large_enough?(url, minimum_width:, minimum_height:)
  width, height = FastImage.size(url, timeout: 5)

  width >= minimum_width && height >= minimum_height
rescue TypeError
  false
end
```

Call it like this:

```ruby
large_enough?(
  "https://example.com/photo.jpg",
  minimum_width: 800,
  minimum_height: 600
)
```

One thing to keep in mind with URLs that users give you: your server is the one making the request. Restrict the allowed hosts or network destinations, so you don't open yourself up to server-side request forgery.

FastImage is a focused tool. It won't resize, optimize or transform an image. But when all you want is the size or the format, it saves you the cost and the extra moving parts of a full image-processing pipeline.
