# Using FastImage to get image dimensions in Ruby

If your app takes image URLs, you often need to know an image's width and height before you download or process the whole image. Maybe you want to check the image, get the image's aspect ratio, save space for the image in a layout, or reject images that are too small.

Ruby's `fastimage` gem was built for exactly this. It determines an image's dimensions by reading only the necessary part of the file, which is much more efficient than downloading the whole image and opening the image with an image processing library.

## Installing FastImage

Add the gem to your `Gemfile`:

```ruby
gem "fastimage"
```

Then install it:

```bash
bundle install
```

Alternatively, install it directly:

```bash
gem install fastimage
```

If you are not using Bundler's automatic loading, require it yourself:

```ruby
require "fastimage"
```

## Reading dimensions from a URL

The main API is `FastImage.size`. You pass it an image URL and it returns an array with the width and the height:

```ruby
url = "https://example.com/images/header.jpg"

width, height = FastImage.size(url)

puts "Width: #{width}px"
puts "Height: #{height}px"
```

For a 1200 by 630 image you get:

```ruby
[1200, 630]
```

This works because the common image formats keep the dimensions in metadata near the start of the image file. FastImage requests just enough data to locate that information, so we never fetch every byte.

If you want to know what kind of image it is, ask for the type:

```ruby
type = FastImage.type(url)

puts type
# => :jpeg
```

FastImage supports the popular formats: JPEG, PNG, GIF, BMP, TIFF, ICO, WebP and SVG.

## Reading local images

It isn't only for remote URLs. FastImage can read images on disk too:

```ruby
width, height = FastImage.size("public/uploads/avatar.png")

puts "#{width}x#{height}"
```

So our code uses the same interface whether the image is local or remote.

## Working out the aspect ratio

Once we have the dimensions, calculating the ratio is straightforward:

```ruby
width, height = FastImage.size(url)

if width && height
  aspect_ratio = width.to_f / height
  puts aspect_ratio.round(2)
end
```

I convert `width` to a float on purpose. It makes the intent clear and it avoids integer division surprises in older Ruby versions.

You can also sort the image by orientation:

```ruby
orientation =
  if width > height
    :landscape
  elsif height > width
    :portrait
  else
    :square
  end
```

I find that useful when selecting thumbnails or deciding how an image should show up in a responsive layout.

## Handling failures

Remote images are unreliable. The URL might be unavailable or slow, or the URL might point at something that isn't a supported image. By default `FastImage.size` can return `nil` when it can't read the dimensions:

```ruby
dimensions = FastImage.size(url)

if dimensions
  width, height = dimensions
  puts "#{width}x#{height}"
else
  puts "Unable to read image dimensions"
end
```

If you'd rather get exceptions, turn on `raise_on_failure`:

```ruby
begin
  width, height = FastImage.size(
    url,
    timeout: 5,
    raise_on_failure: true
  )

  puts "#{width}x#{height}"
rescue FastImage::ImageFetchFailure => e
  warn "Could not fetch image: #{e.message}"
rescue FastImage::UnknownImageType => e
  warn "Unsupported image: #{e.message}"
end
```

The timeout is there so a slow server can't tie up your application indefinitely.

## Validating image dimensions

I like to wrap the check in a small helper so it can be reused as validation:

```ruby
def large_enough?(url, minimum_width:, minimum_height:)
  width, height = FastImage.size(url, timeout: 5)

  width >= minimum_width && height >= minimum_height
rescue TypeError
  false
end
```

Use it like this:

```ruby
large_enough?(
  "https://example.com/photo.jpg",
  minimum_width: 800,
  minimum_height: 600
)
```

If the URLs come from users, remember that it's your server making the request to that URL. I'd restrict which hosts or network destinations are allowed, to reduce the risk of server-side request forgery.

FastImage does one thing. It won't resize, optimize or transform images. But when all I need is the size or the format, it saves me the cost and the complexity of a full image processing pipeline.
